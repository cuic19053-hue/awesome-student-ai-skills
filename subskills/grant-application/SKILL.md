# 国家助学金申请书

协助学生梳理申请材料、起草申请书并导出可编辑的 `.docx` 草稿。以学校通知和学生提供的资料为依据；不认定申请资格，不替学校判断困难程度或资助档次。

## 政策与金额

仓库采用财教〔2024〕181 号《关于调整高等教育阶段和高中阶段国家奖助学金政策的通知》作为政策范围参考：自 **2024 年秋季学期**起，本专科生国家助学金平均资助标准提高到每生每年 **3700 元**，高校在每生每年 **2500—5000 元**范围内自主确定具体标准，可以分为 **2—3 档**。

- 平均标准不是每名学生的应领金额；上述范围也不确定某校每档具体金额。
- **没有全国统一的“一等／二等／三等”金额对照表。** 不根据困难等级、地区、他校做法或旧例子推算学校金额。
- `grant_level` 和 `difficulty_level` 分别记录学校的资助档次和困难认定结果，两者关系应查学校通知，不自动建立一一对应。
- 用户没有给出学校当年明确金额时，`grant_amount` 留空或设为 `null`，正文写“具体金额待核对学校当年标准”。禁止用零元、平均标准或演示金额补空。
- 金额在范围内也不能证明通知适用、资格合格或金额正确。不同年度、培养层次或专项资助需另查适用规定。
- 不再使用旧版文档中的“2024 年 7 月 1 日起统一分档”和无核验依据的文号。申请书通常不必堆砌政策文号；学校要求引用时核对原文及适用年度。

政策来源应优先查询财政部、教育部官网的同名通知及学校当年资助通知。未提供通知时可以形成待核对的文字草稿，不声称政策核验已完成。

## 适用范围

本 Skill 处理本专科生国家助学金申请书。国家奖学金和国家励志奖学金使用各自 Skill；退役士兵专项、研究生资助及校内临时困难补助应先确认项目类型与适用办法。

助学金写作侧重真实家庭经济情况、就学负担和资助需求。不要把学习排名或科研成果当成全国统一的助学金申请门槛。能否申请、是否需要完成困难认定、应提交哪些证明，由学校当年规则及负责部门确认。

## 信息采集

先问学校、申请学年、已有通知或模板，以及学生希望先梳理材料还是直接起草。每轮只补充当前写作必需的缺项，已有明确资料不重复询问。

| 信息 | 对应字段 | 处理方式 |
|---|---|---|
| 姓名、学院、专业、年级 | `name`, `college`, `major`, `grade` | 保留学生原话，缺少时标待补充 |
| 学号、班级、日期 | `student_id`, `class_name`, `apply_date` | 仅按模板需要采集，不猜学号或日期 |
| 申请学年 | `apply_year` | 缺少时标“申请学年待补充”，不默认往年 |
| 学校资助档次及金额 | `grant_level`, `grant_amount` | 从学校当年明确标准填写，不从等次计算 |
| 困难认定状态 | `difficulty_level`, `difficulty_cert_no`, `poverty_category` | 只记录已有认定，未认定不能写成已获认定 |
| 家庭情况与就学负担 | `family_situation` | 学生愿意提供的收入、支出、人口和来源；不要求编造困难经历 |
| 在校表现 | `study_situation`, `position_work`, `volunteer_detail` 等 | 只采用实际提供的经历，不强制补科研或勤工助学 |
| 申请理由及用途 | `application_reason`, `tuition`, `textbook_fee` 等 | 根据真实支出与需求说明 |

用户不愿在正文写收入、证明编号或家庭成员姓名时，尊重其选择。可询问是否用概括表达，不把缺失或隐私选择当作编造依据。最终正式申报所需资料应由用户按学校要求另行提供。

## 写作结构

学校表格和实际栏目优先。无模板时可按以下五段形成书信体草稿：

1. **个人基本情况**：申请目标、学年与学生基本信息。金额未知就留待核对，不写成已经确定的应领金额。
2. **家庭经济情况**：基于已提供的收入来源、人口、主要支出和就学负担说明困难；没有大额支出、失业或疾病就不添加。
3. **在校表现**：真实学习、生活及服务经历；没有某类经历可以不写。
4. **申请理由**：资助需求、计划用途和已有自助安排，区分“已完成”与“拟开展”。
5. **态度与落款**：表达申请意愿及本人可确认的承诺；不替学校作通过或发放保证。

称呼、此致敬礼、签名和日期按学校要求填写。800／1200／1500 是仓库提供的写作篇幅选项，不是所有学校的硬性门槛。真实资料不足时先给较短、有占位的草稿，不靠扩充虚构经历凑字数。

## JSON 字段与构建

以下是**空白采集结构**，不是学生事实或完整正式申报表。`null` 和空数组表示未提供；生成前由学生核对将进入正文的内容。

完整空白结构见 [JSON 字段结构](references/json-schema.md)，构造输入时再读取；未知值用 null 或空数组，不补入演示事实。

`family_members` 如实际需要，可填写 `name`、`relation`、`job`、`income`、`political`。`work_study` 有真实经历时可填写 `position`、`place`、`duration`、`monthly_income`，没有就保持空数组。

构建器还接受 `opening`、`family_economy`、`ideology`、`party_history`、`study_situation`、`application_reason`、`gratitude` 等已由学生确认的段落。优先传入审阅过的正文，避免把构建器的通用语句误作个人事实；自定义正文中的金额和日期也须人工核对。

```bash
python subskills/grant-application/build.py --data data.json --out application-draft.docx
```

可选 `--school pku`、`--school tsinghua`、`--school whu`、`--school zju` 应用仓库的通用版式适配。这些适配不等于学校最新正式模板。无匹配模板时核对实际输出。

`--demo` 只用于合成示例与排版检查，不可将演示人物或经历替换姓名后直接提交。

**每个句子都必须能落到具体的人、事、时间、数字或对象上；落不到的句子，删掉。**

### 句式要求

1. **长短句交替**：每 3~5 句里至少有一句 ≤12 字或 ≥60 字。
2. **一段一个事实**：段首句不要用「在……方面」。
3. **少用第一人称抒情**：「我深深感到」「我深刻认识到」一律删除。
4. **事实优先**：仅用用户确认的数字；次数或数量未知时追问或保留原意。
5. 不用破折号堆叠解释，不连续套用「不仅……而且……」。

### 冲突处理

政策条文、领导讲话、文件原名**允许庄重书面语**，不算套话。
检测时加 `--allow-policy-quotes`（该维度扣分减半）。
但引用必须写成 `《文件全名》（发文号）`，且只引与论点直接相关的 1~2 句。

### 反模式

- ❌ 把子 skill 里的「金句模板」当范文直接套用
- ❌ 用排比段凑字数
- ❌ 通篇无一个数字、无一个专有名词
- ❌ 仅凭检测分数决定交付，或为提高分数编造事实
- ❌ 只删套话不补事实（删完变空段落，同样不及格）

## 质检清单与导出核对

- 核对通知的学校、学年、培养层次、项目名称、金额和档次；需要时记录通知链接及发布日期。
- 核对每一项个人与家庭事实、收入单位和时间范围，删除学生要求省略的信息。
- 金额和申请学年未知时保留待核对提示，不把构建成功当作信息完整。
- 学校的困难认定线和资助资格由学校确认，不能按仓库中的历史经验值判断。
- 检查 Word 中的空白、占位、家庭表格、签名、日期与分页。构建器的警告只辅助检查，不作正式审核。
- 最终交付可编辑的 Word **草稿**及尚需补充事项。只有申报人按学校要求核对后才决定是否提交。
