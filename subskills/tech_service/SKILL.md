# 三下乡社会实践-科技服务类 Skill

本 skill 处理"大学生暑期三下乡社会实践-科技服务类"立项申报书全流程：信息采集 → 服务需求分析 → 专业能力匹配 → 服务方案设计 → 按场次实施 → docx 生成 → 质检。仅处理"科技服务类"子类（科技/医疗/法律/农业技术服务为主），调研/支教/宣讲类请走对应 skill。

科技服务类与调研/支教/宣讲类的核心区别在于"专业输出"——评审看的是服务专业性、需求匹配度、可持续性，而非数据采集（调研）、教学方法（支教）或一对多传达（宣讲）。科技服务类申报书必须有：服务对象需求清单 + 专业能力匹配矩阵 + 按服务场次实施方案 + 服务人次与解决方案量化产出 + 持续帮扶机制。

输出文件：可提交的 .docx（A4 纸张，宋体小四正文，黑体三号标题，1.5 倍行距，首行缩进 2 字符）。

---

## 一、适用场景与触发条件

**适用**：用户提到"三下乡""社会实践""科技服务""医疗服务""法律援助""农业技术指导""IT 维修""电商培训""数字素养培训""上门服务""暑期社会实践立项申报书"等关键词，且实践主要形式为面向村民/社区居民提供专业技术服务（非走访调研、非中小学支教、非集中宣讲）。

**不适用**（需走其他 skill）：
- 调研类（含问卷 + 访谈，调研报告为核心产出）→ 走 social_survey skill
- 支教类（含课时安排、教学对象为中小学生、有教案）→ 走 volunteer_teaching skill
- 宣讲类（含宣讲场次、一对多集中传达、宣讲大纲）→ 走 policy_lecture skill
- 单纯志愿服务（无专业技术服务输出，如敬老陪伴）→ 走志愿服务 skill

**四种服务子方向速查**：

| 子方向 | 典型选题 | 专业背景要求 | 服务对象 |
|--------|----------|--------------|----------|
| 科技服务 | IT 维修、电商培训、数字素养、智能手机使用 | 计算机/通信/电子/电子商务 | 村民、村电商、留守老人 |
| 医疗服务 | 健康体检、慢病管理、急救培训、中医药科普 | 临床医学/护理/药学/公共卫生 | 村民、老年人、慢病患者 |
| 法律援助 | 民法典宣讲与咨询、反诈、未成年人保护、土地纠纷 | 法学/知识产权 | 村民、妇女、外出务工人员 |
| 农业技术指导 | 种植技术、养殖防疫、农机使用、农产品加工 | 农学/园艺/植物保护/动物科学 | 种养殖大户、合作社、家庭农场 |

**触发条件组合**：用户输入包含"三下乡/社会实践" + "科技服务/医疗服务/法律援助/农业技术指导/IT 维修/电商培训/数字素养"中任一 → 进入本 skill。

**默认假设**：未明确说明时默认为科技服务子方向（覆盖最广、立项通过率最高、与高校学科匹配度最高）。用户若指向其他三类，按对应子方向调整服务内容与专业要求。

**科技服务类 vs 其他子类核心区别**：
- 科技服务类：核心产出是"服务人次 + 解决方案 + 持续帮扶机制"，强调专业输出
- 调研类：核心产出是"调研报告"，强调数据收集与分析
- 支教类：核心产出是"支教课时 + 学生反馈"，强调教学方法
- 宣讲类：核心产出是"宣讲场次 + 受众覆盖"，强调内容传达

## 二、工作流程总览

```
1. 子方向确认
   → 确认服务子方向（科技/医疗/法律/农业）→ 锁定服务对象类型
   → 明确团队专业能力是否匹配（必须有对应学科背景成员）
2. 信息采集
   → 通用 10 字段 + 服务专属 12 字段（详见第三章）
   → 分批追问，不替用户编造服务能力
3. 服务需求分析
   → 调研服务对象实际需求 → 列出需求清单 → 按优先级排序 → 匹配团队专业能力
4. 专业能力匹配
   → 团队成员专业背景 → 服务内容 → 匹配度评估（高/中/低）
   → 低匹配项必须由指导教师补充或调整服务内容
5. 服务方案设计
   → 每项需求对应 1 套解决方案（服务流程 + 工具 + 预期解决程度）
   → 总服务场次 5~8 场，覆盖 150~300 人次
6. 按场次实施安排
   → 每场：场次序号 + 日期 + 地点 + 服务对象 + 服务内容 + 人数 + 专业要求
   → 5~8 行覆盖整个实践期
7. 持续帮扶机制
   → 建立"线上 + 线下"长效服务，每月 1 次远程答疑，每季度 1 次现场回访
8. docx 生成
   → python build.py --data data.json --out output.docx
9. 质检
   → 专业匹配度 + 需求匹配度 + 场次人数加总 + 持续机制可行性
```

**关键节点控制**：
- 子方向确认阶段不锁定服务对象前不进入需求分析，避免后期返工
- 需求分析必须先列"需求清单"再设计服务方案——脱离需求的服务是无效服务
- 专业能力匹配必须列矩阵表，低匹配项必须由指导教师补充
- 按场次表必须按"日"为粒度列出（不能用"前期/中期/后期"）
- 预期成果必须以"服务人次 + 解决方案 + 持续帮扶机制"为主，不能只写"扩大影响"

**与调研/支教/宣讲的边界判定**：科技服务类有"上门 + 维修/培训/咨询"特征，强调"一对一解决问题"或"小班技能培训"；调研类有"问卷+访谈"特征；支教类有"中小学生+课时"特征；宣讲类有"一对多集中传达"特征。混合实践以主要形式归类，科技服务占比 ≥ 60% 归本 skill。

**申报书字数与篇幅**：科技服务类申报书 4500~6500 字为宜，封面+11 栏目+签字页，约 8~12 页 A4。

## 三、信息采集清单

### 3.1 通用必采（10 字段）

| 字段 | 说明 | 示例 |
|------|------|------|
| 团队名称 | 含"赴+地点+主题+服务团" | 赴 XX 县数字赋能科技服务团 |
| 实践主题 | 团中央年度主题 | 乡村振兴 青春建功 |
| 实践地点 | 精确到村/社区 | XX 省 XX 县 XX 镇 3 个行政村 |
| 实践时间 | 含出发返程 | 2025.07.15-07.21（7 天） |
| 团队人数 | 5~12 人为佳（小而精） | 5 人 |
| 队长信息 | 姓名/学号/专业/年级/电话 | 张三/202212345/计算机 2022 级/大三/138XXXXXXXX |
| 指导教师 | 姓名/职称/电话/是否随队 | 李教授/副教授/139XXXXXXXX/随队 |
| 申报单位 | 学院全称 | 计算机科学与技术学院 |
| 申报日期 | 中文格式 | 2025 年 5 月 20 日 |
| 成员信息 | 每人 5 字段 | 姓名/学号/专业/分工/电话 |

### 3.2 科技服务类专属必采（12 字段）

**A. 服务子方向与对象**
1. 服务子方向：科技/医疗/法律/农业四选一（可主+辅，主方向占比 ≥ 70%）
2. 服务对象类型：村民/留守老人/种养殖大户/村电商/村干部/外出务工人员（多选）
3. 服务对象规模：单场 20~60 人，总覆盖 150~300 人次
4. 服务对象需求来源：当地团委反馈 / 实地预调研 / 政府部门委托函

**B. 需求与方案**
5. 服务对象需求清单：3~6 项核心需求（如"智能手机使用 + 电商开店 + 反诈 + 视频通话"）
6. 需求优先级排序：高/中/低（按需求紧迫程度 + 团队能力匹配度综合排序）
7. 团队专业能力匹配矩阵：每项需求 × 团队成员专业 → 匹配度评估
8. 解决方案设计：每项需求对应 1 套方案（服务流程 + 工具 + 预期解决程度）

**C. 场次与产出**
9. 服务场次：5~8 场为宜，单场 20~60 人，总覆盖 150~300 人次
10. 单场时长：60~180 分钟（培训类 90~120 分钟、维修类 60~180 分钟、咨询类 30~60 分钟/人）
11. 服务记录方式：签到表 + 服务记录单 + 满意度反馈表 + 解决方案手册
12. 持续帮扶机制：线上答疑群 + 月度回访 + 季度现场服务 + 学年度长效接力

### 3.3 保障与经费

| 类别 | 必采字段 | 示例 |
|------|----------|------|
| 安全 | 应急联系人 3 名、应急流程分级、保险购买情况 | 平安短期意外险 30 万保额 |
| 宣传 | 校内/校外/新媒体三类平台 + 发布篇数 | 中青网 1 + 校团委 2 + 抖音 3 |
| 预算 | 交通/食宿/物资/印刷/其他 5 项 + 金额 + 计算依据 | 物资 1500 元 = U 盘 50×20 + 维修工具 400 + 培训手册 100×6 |
| 物资清单 | 维修工具/培训手册/反诈单页/小礼品 | 维修工具包 5 套 + 培训手册 100 份 + 反诈单页 200 份 |

### 3.4 字段优先级

| 优先级 | 字段 | 缺失影响 |
|--------|------|----------|
| P0 必填 | 团队名称/主题/地点/时间/队长/指导教师/服务子方向/需求清单/专业能力匹配 | 申报书退回重填 |
| P1 重要 | 团队人数/成员分工/按场次表/服务方案/安全预案/预期成果/持续帮扶机制 | 评审扣大分 |
| P2 推荐 | 经费计算依据/宣传计划/学校审批/团中央专项报送 | 评审加分项 |

### 3.5 追问话术

**子方向相关**：
- 用户说"做三下乡服务"→ 追问"四类子方向选哪类？科技服务/医疗服务/法律援助/农业技术指导？"
- 用户说"科技服务"→ 追问"具体做哪些？IT 维修/电商培训/数字素养/反诈宣讲？"
- 用户说"我们都是计算机专业"→ 追问"匹配哪些需求？智能手机/电脑维修/办公软件/电商开店？"

**需求与对象相关**：
- 用户说"村民需要"→ 追问"需求是哪儿来的？当地团委反馈？实地预调研？政府部门委托函？"
- 用户说"教村民用手机"→ 追问"具体哪几个场景？微信视频/扫码支付/反诈识别/拍照定位？"
- 用户说"覆盖村里人"→ 追问"具体哪几类？留守老人/种养殖大户/村电商/村干部？每类预计多少人次？"

**专业匹配相关**：
- 用户说"我们团队能修电脑"→ 追问"团队成员具体什么专业？硬件维修能力还是软件维护能力？是否需要指导教师补充？"
- 用户说"我们指导老师是医学教授"→ 追问"老师能全程随队吗？医疗服务是否需要医师执业资格证？是否需要与当地卫生院联合开展？"
- 用户说"法律援助"→ 追问"团队成员是否有法考经验？指导老师是否执业律师？是否能出具书面法律意见？"

**场次与产出相关**：
- 用户说"5 场服务"→ 追问"每场日期 + 地点 + 对象 + 服务内容 + 人数 + 专业要求？能不能列成表？"
- 用户说"维修 50 台电脑"→ 追问"维修记录单怎么存档？故障分类统计？是否提供 30 天质保？"
- 用户说"培训村民"→ 追问"培训手册印多少份？是否录视频供回看？后续线上答疑怎么组织？"

### 3.6 采集纪律

1. 分批提问：先采 P0 通用 10 字段，再采 P0 服务专属 8 字段，最后采 P1/P2
2. 不替用户编：拿不准的事实，让用户去查证后再填（如指导教师职称、保单号、当地委托函）
3. 保留原话：用户口述的经历可保留原意但用书面语整理，不要过度升华
4. 复述确认：信息采完后，按 11 栏目顺序复述给用户确认，再进入撰写阶段
5. 专业匹配校对：采集完成后单独校对一遍团队成员专业与服务内容的匹配度（详见 §七）

## 四、栏目结构详解

科技服务类申报书固定 11 栏目，缺一不可。各栏目字数与评审权重已在 §十 给出。

```
封面：项目名称、团队名称、申报单位、申报日期
（封面副标题标注"科技服务类"，与调研/支教/宣讲类区分）

一、团队基本信息（表格 7 行 2 列）
  - 团队名称（赴+地点+主题+服务团）
  - 实践主题（团中央年度主题）
  - 实践地点（精确到村）
  - 实践时间（精确到日，7~15 天）
  - 团队人数（5~12 人，小而精）
  - 队长（姓名/学号/专业/年级/电话）
  - 指导教师（姓名/职称/电话/是否随队/专业方向）

二、团队成员信息表（5 列）
  | 姓名 | 学号 | 专业年级 | 团队分工 | 联系方式 |
  - 分工必须具体到"做什么"，不能只写"成员"
  - 科技服务类建议分工：主讲 / 维修操作 / 培训助教 / 记录归档 / 后勤保障
  - 团队示例：5 人含计算机 3 + 通信 2，专业互补覆盖硬件/软件/网络

三、实践主题与背景（400~600 字，3 段）
  - 团中央主题对应（150 字）
  - 服务子方向选定理由（200 字）
  - 实践对象基本情况（150 字，含数字化水平/医疗服务可及性/法律意识等数据）

四、实践目的与意义（300~500 字，2 段）
  - 对当地：服务 N 人次 + 解决 X 类具体问题 + 建立 Y 项持续帮扶机制
  - 对学生：专业知识应用 + 服务意识培养 + 基层国情认识

五、实践内容与实施方案【重点，800~1200 字】
  - 实践形式：科技服务类（说明与调研/支教/宣讲的边界）
  - 服务对象需求分析：需求清单 + 优先级
  - 按场次实施安排表（核心）
    | 场次 | 日期 | 地点 | 服务对象 | 服务内容 | 人数 | 专业要求 |
    每场对应 1 行，5~8 场
    底部合计：N 场 × M 人次 = 总服务人次

六、服务方案【科技服务类专属，独立栏目】
  - 子方向：科技服务（IT 维修 + 电商培训 + 数字素养）
  - 结构化表格：
    | 需求 | 匹配专业能力 | 服务流程 | 预期解决方案 |
    每项需求对应 1 行
  - 每项配"持续帮扶机制"：线上答疑群 + 月度回访 + 季度现场服务

七、安全保障预案（300~500 字，5 段）
  - 出行安全 / 人身安全 / 应急联系人 / 应急流程 / 保险购买
  - 服务类专属安全：维修类带电作业安全 / 医疗服务消毒规范 / 法律援助免责声明

八、预期成果（必须可量化）
  - 服务场次：N 场
  - 服务人次：M 人次（村民 N1 + 老人 N2 + 大户 N3 + 干部 N4）
  - 解决方案：X 套（IT 维修方案 Y 套 + 电商开店方案 Z 套 + 数字素养培训方案 W 套）
  - 服务记录：签到表 N 份 + 维修记录单 Y 份 + 培训手册 Z 份
  - 持续帮扶机制：线上答疑群 1 个 + 月度远程答疑 + 季度现场回访 + 学年度接力
  - 新闻稿：X 篇（中青网/校团委/学院公众号）
  - 短视频：Y 个

九、经费预算（5 类标准科目 + 计算依据）
  | 预算科目 | 金额（元） | 计算依据 |
  - 交通费 / 食宿费 / 物资费 / 印刷费 / 其他
  - 科技服务类物资费占比建议 30~40%（维修工具 + U 盘 + 培训手册）

十、宣传计划
  - 校内媒体（团委公众号、校报）
  - 校外媒体（中青网、地方媒体）
  - 新媒体平台（抖音、B 站、视频号）

十一、指导教师意见 + 学院团委意见
  - 双栏预留签字空间（空 6 行 + 签字行 + 日期行）
```

**栏目顺序固定**：1→11，不能调整。学校下发模板若有微调，按学校模板填，但 11 栏目齐全。

**字数控制**：总字数 4500~6500 字。封面 100 字、一/二表 200 字、三 500 字、四 400 字、五 1000 字、六 600 字、七 400 字、八 300 字、九 200 字、十 200 字、十一签字 100 字。

**栏目间逻辑链**：主题（三）→ 目的（四）→ 实施方案（五）→ 服务方案（六）→ 安全（七）→ 成果（八）→ 经费（九）→ 宣传（十）。前栏目铺垫，后栏目落地，不能脱节。

**科技服务类独有栏目**：六、服务方案——这是科技服务类与调研/支教/宣讲类最显著的区别。调研类有"问卷设计"栏目，支教类有"教案"栏目，宣讲类有"宣讲大纲"栏目，科技服务类有"服务方案"栏目。

**封面副标题**：必须标注"科技服务类"，便于评审一眼定位子类。常见格式：`（XX 主题·科技服务类）`。

**五、六两栏联动**：实施方案的按场次表是"在哪服务、服务几场、谁接受服务"，服务方案是"每项需求怎么解决、用什么工具、解决到什么程度"。两者必须对应——场次表的服务内容总和 = 服务方案的解决项数。

### 4.2 各栏目字数与表格规范

**封面**：项目名称（一行 25 字内）、团队名称（一行 20 字内）、申报单位（学院全称）、申报日期（XXXX 年 X 月 X 日）。无表格。副标题一行：`（XX 主题·科技服务类）`。

**一、团队基本信息**：7 行 2 列表格，列宽 [4.5cm, 11.5cm]。表头加粗居中，数据居中。"队长"字段一行写完姓名/学号/专业/年级/电话（用斜杠分隔）。"指导教师"字段含"专业方向"（如"软件工程/物联网"），便于评审判断专业匹配度。

**二、团队成员信息表**：5 列表格，列宽 [2.5, 2.8, 3.5, 3.5, 3.7]cm。成员数 ≤ 12 人（科技服务类小团队为佳，专业互补）。每行分工必须具体到"做什么"（如"主讲 IT 维修 + 维修操作"），不能只写"成员"。

**三、实践主题与背景**：3 段共 400~600 字。第 1 段团中央主题对应；第 2 段服务子方向选定理由（结合当地需求 + 团队专业）；第 3 段实践对象基本情况（必须有数据，如"5 个行政村 60 岁以上老人 1240 人，智能手机持有率 68%，但能独立完成视频通话的仅 23%"）。

**四、实践目的与意义**：2 段共 300~500 字。对当地段必须含三项量化：服务人次 + 解决问题数 + 持续帮扶机制。对学生段必须含三项提升：专业知识应用 + 服务意识培养 + 基层国情认识。

**五、实践内容与实施方案**：3 子节共 800~1200 字。（一）实践形式 150 字，说明科技服务类与调研/支教/宣讲的边界；（二）服务对象需求分析 300 字，列出 3~6 项需求 + 优先级；（三）按场次实施安排表 7 列 N 行（5~8 场），底部合计场次与总服务人次。

**六、服务方案**：4 列结构化表格，列宽 [3.5, 3.5, 5.5, 3.5]cm。表头：需求 / 匹配专业能力 / 服务流程 / 预期解决方案。每项需求对应 1 行。表后追加"持续帮扶机制"小节（150 字）：线上答疑群 + 月度远程答疑 + 季度现场回访 + 学年度接力。

**七、安全保障预案**：5 段共 300~500 字。除通用安全外，必须含服务类专属安全：（1）维修类带电作业安全（断电操作、防静电、工具绝缘）；（2）医疗服务消毒规范（一次性器械、医疗废物处理）；（3）法律援助免责声明（不撰写诉讼文书、复杂案件转介）。

**八、预期成果**：以项目符号列出 6~8 项，必须可量化。核心三项：服务场次 + 服务人次 + 解决方案数。其他：服务记录归档 + 持续帮扶机制 + 新闻稿 + 短视频。禁止写"取得良好效果""扩大项目影响"等空话。

**九、经费预算**：5 类标准科目（交通/食宿/物资/印刷/其他）3 列表格，列宽 [3.5, 3.0, 9.5]cm。金额非整数 + 计算依据。科技服务类物资费占比 30~40%（维修工具 + U 盘 + 培训手册）。底部合计行自动加总。

**十、宣传计划**：3 类媒体各 1 段。校内媒体（校团委公众号 + 校报 + 学院公众号）、校外媒体（中青网 + 地方电视台 + 地方日报）、新媒体（B 站 + 抖音 + 微信视频号）。发布时间节点：启动报道 + 中期进展 + 结项报道。

**十一、指导教师意见 / 学院团委意见**：双栏预留签字空间，每栏空 6 行 + 签字行 + 日期行。学校审批意见为可选项（include_school_approval=True 时追加）。

### 4.3 栏目间衔接逻辑

科技服务类 11 栏目构成一条完整逻辑链：服务对象基本情况（三）→ 团队能力匹配（一/二）→ 服务需求清单（五）→ 服务方案（六）→ 持续帮扶机制（六/八）→ 服务记录归档（八）。每个栏目的"输入"是上一栏目的"输出"。

**衔接检查清单**：
- 三的实践对象基本情况 ↔ 五的服务对象需求清单（需求必须来自对象实际情况）
- 一/二的团队专业 ↔ 六的匹配专业能力（能力列必须用团队专业）
- 五的场次表服务内容 ↔ 六的需求项（场次内容必须对应需求项）
- 五的场次表合计人次 ↔ 八的预期成果人次（数字必须一致）
- 六的服务方案 ↔ 八的解决方案数（方案数 = 预期成果中的方案数）
- 六的持续帮扶机制 ↔ 八的机制描述（措辞与安排必须一致）

## 五、各栏目撰写规范

### 5.1 通用规范

- 字体字号：正文宋体小四，标题黑体三号，表格宋体五号（详见 writing_guide.md §1.1）
- 段落：1.5 倍行距，首行缩进 2 字符，段前后 0 行
- 标点：中文全角，不混用中英文标点
- 序号体系：一、（一级）/（一）（二级）/1.（三级）/（1）（四级），不混用 1.1/1.1.1
- 数据：所有数据必须有出处（团中央文件/统计公报/实地预调研/当地委托函）
- 量化：禁止"若干""一定""相关"，必须写具体数字
- 专业表述：科技服务类必须用专业术语（如"操作系统""驱动程序""主板检测"），不用口语化表达

### 5.2 各栏目专属规范

**封面副标题**：固定格式 `（XX 主题·科技服务类）`，与调研类/支教类/宣讲类形成区分。

**一、团队基本信息**：科技服务类团队人数 5~12 人（小团队为佳，专业互补）。团队名称含"服务团"三字（如"赴 XX 县数字赋能科技服务团"）。指导教师字段含"专业方向"。

**二、团队成员信息表**：分工必须含动词（如"主讲 IT 维修 + 维修操作""培训助教 + 签到管理"）。团队成员专业必须有明确学科分布（如"计算机 3 + 通信 2"，覆盖硬件/软件/网络）。

**三、实践主题与背景**：第 3 段实践对象基本情况必须有量化数据。科技服务子方向需含数字化水平数据；医疗服务子方向需含慢病发病率/就医距离；法律援助子方向需含纠纷类型分布；农业技术指导子方向需含主导产业规模。

**四、实践目的与意义**：对当地段必须含三项量化——服务人次（如"覆盖 200 人次"）+ 解决问题数（如"修复电脑 50 台 + 电商开店 20 户"）+ 持续帮扶机制（如"建立线上+线下长效服务，每月 1 次远程答疑"）。对学生段强调"专业知识应用"——把课堂所学带到基层。

**五、实践内容与实施方案**：3 子节结构固定。（一）实践形式 150 字说明子方向与边界；（二）服务对象需求分析 300 字列需求清单 + 优先级（高/中/低）；（三）按场次实施安排表 7 列：场次/日期/地点/服务对象/服务内容/人数/专业要求。底部合计行。

**六、服务方案**：4 列结构化表格。每项需求对应 1 行。表后必须追加"持续帮扶机制"小节，含线上答疑群 + 月度远程答疑 + 季度现场回访 + 学年度接力。机制可行性是评审重点。

**七、安全保障预案**：除通用 5 段外，必须含服务类专属安全。维修类：断电操作、防静电、工具绝缘；医疗类：一次性器械、医疗废物处理、与当地卫生院联合；法律类：不撰写诉讼文书、复杂案件转介律所、签署咨询免责声明。

**八、预期成果**：6~8 项项目符号列表。核心三项：服务场次（N 场）+ 服务人次（M 人次，分类统计）+ 解决方案数（X 套，分类统计）。其他：服务记录归档 + 持续帮扶机制 + 新闻稿（明确发布平台与篇数）+ 短视频（明确时长与平台）。

**九、经费预算**：5 类标准科目 + 物资清单。科技服务类物资费占比 30~40%（维修工具 + U 盘 + 培训手册 + 反诈单页 + 小礼品）。计算依据必须含单价 × 数量。

**十、宣传计划**：3 类媒体各 1 段，发布时间节点必须含启动/中期/结项三个时点。中青网投稿必须有（团中央官方平台）。

**十一、签字栏**：双栏预留，每栏空 6 行 + 签字行 + 日期行。学校审批意见可选。

## 六、服务需求分析方法

### 6.1 需求清单构建

服务对象需求清单是科技服务类申报书的"地基"。需求不清，方案就是空中楼阁。

**需求来源（三选一或组合）**：
1. 当地团委反馈：团县委/镇团委梳理辖区内年度需求清单
2. 实地预调研：实践前 1 个月派 2 名队员赴地走访 1~2 天，访谈村干部 + 部分村民
3. 政府部门委托函：县/镇相关部门（如农业农村局、卫健局、司法局）出具的服务需求委托函

**需求清单格式**（3~6 项为佳）：

| 序号 | 需求描述 | 服务对象 | 紧迫程度 | 团队能力匹配 |
|------|----------|----------|----------|--------------|
| 1 | 智能手机基础操作（视频通话/扫码支付） | 留守老人 | 高 | 高（计算机专业） |
| 2 | 电脑故障维修与系统重装 | 村民 + 村电商 | 高 | 高（计算机专业） |
| 3 | 电商开店与直播带货基础 | 村电商 + 致富带头人 | 中 | 中（需电商知识补充） |
| 4 | 网络反诈识别 | 全体村民 | 高 | 中（需法律知识补充） |
| 5 | 数字素养（政务 App/健康码使用） | 村民 | 中 | 高（计算机专业） |

### 6.2 需求优先级排序

优先级 = 紧迫程度 × 团队能力匹配度：

- **高优先级**：紧迫程度高 + 团队能力匹配高 → 必做，安排主力场次
- **中优先级**：紧迫程度高 + 团队能力匹配中，或紧迫程度中 + 团队能力匹配高 → 做，配合指导教师补充
- **低优先级**：紧迫程度中 + 团队能力匹配中 → 选择性做，或转为宣讲类轻量化处理

**反例**：❌ "村民需要什么我们就做什么"——无优先级，方案散乱
**正例**：✅ "5 项需求中 3 项高优先级（智能手机/电脑维修/反诈），2 项中优先级（电商/数字素养），高优先级安排 4 场主力服务，中优先级各安排 1 场"

### 6.3 需求与团队能力匹配度评估

匹配度评估矩阵（每项需求 × 每位成员）：

| 需求 \ 成员 | 张三（计算机） | 李四（计算机） | 王五（计算机） | 赵六（通信） | 钱七（通信） | 综合匹配度 |
|-------------|----------------|----------------|----------------|--------------|--------------|------------|
| 智能手机操作 | 高 | 高 | 高 | 高 | 高 | 高 |
| 电脑维修 | 高 | 高 | 中 | 中 | 低 | 高 |
| 电商开店 | 中 | 中 | 低 | 中 | 中 | 中 |
| 网络反诈 | 中 | 低 | 中 | 高 | 中 | 中 |
| 数字素养 | 高 | 高 | 高 | 高 | 高 | 高 |

**低匹配项处理**：必须由指导教师补充（如指导教师为法学背景，可补强反诈类需求）或调整服务内容（如将"电商开店"调整为"电商基础认知"）。禁止"团队无能力却硬上"——评审会扣专业性分。

### 6.4 需求清单与按场次表的对应

需求清单的每项高优先级需求至少对应 1 个服务场次。需求清单与服务方案的对应关系必须 1:1（每项需求 1 套解决方案）。场次表底部合计 = 需求清单各项服务人次之和。

### 6.5 不同子方向的需求清单示例

**科技服务子方向需求清单示例**（5 项）：
1. 智能手机基础操作（视频通话/扫码支付）— 留守老人 — 高紧迫 — 高匹配
2. 电脑故障维修与系统重装 — 村民/村电商 — 高紧迫 — 高匹配
3. 电商开店与直播带货基础 — 村电商 — 中紧迫 — 中匹配
4. 网络反诈识别 — 全体村民 — 高紧迫 — 中匹配
5. 数字素养（政务 App/健康码） — 村民 — 中紧迫 — 高匹配

**医疗服务子方向需求清单示例**（5 项）：
1. 慢病管理（高血压/糖尿病） — 老年人 — 高紧迫 — 高匹配（临床医学）
2. 急救知识与心肺复苏 — 村干部/家长 — 高紧迫 — 高匹配
3. 中医药科普与体质辨识 — 老年人 — 中紧迫 — 高匹配（中医学）
4. 妇幼健康咨询 — 妇女/孕产妇 — 中紧迫 — 高匹配（护理）
5. 健康体检与基础筛查 — 全体村民 — 高紧迫 — 中匹配（需医疗设备支持）

**法律援助子方向需求清单示例**（5 项）：
1. 民法典婚姻家庭编咨询 — 妇女 — 高紧迫 — 高匹配（法学）
2. 反诈与消费者权益保护 — 全体村民 — 高紧迫 — 中匹配
3. 土地承包纠纷咨询 — 种养殖大户 — 中紧迫 — 高匹配（法学）
4. 未成年人保护法宣讲 — 家长/青少年 — 高紧迫 — 高匹配
5. 外出务工维权咨询 — 外出务工人员 — 中紧迫 — 中匹配

**农业技术指导子方向需求清单示例**（5 项）：
1. 主导作物种植技术 — 种植大户 — 高紧迫 — 高匹配（农学）
2. 养殖防疫技术 — 养殖户 — 高紧迫 — 高匹配（动物科学）
3. 农机使用与维护 — 家庭农场 — 中紧迫 — 高匹配（农业工程）
4. 农产品加工与品牌建设 — 合作社 — 中紧迫 — 中匹配
5. 农产品质量安全 — 种养殖大户 — 中紧迫 — 高匹配

### 6.6 需求清单常见错误

- ❌ 需求 10 项以上：评审看不过来，重点不突出 → ✅ 需求 3~6 项，聚焦核心，每项做透
- ❌ 需求无优先级：所有需求平列，方案散乱 → ✅ 需求分高/中/低三档，高优先级主力场次
- ❌ 需求与团队能力严重不匹配：如文科团队做 IT 维修 → ✅ 高匹配 ≥ 60%，低匹配项由指导教师补强
- ❌ 需求描述模糊：如"村民需要技术帮助" → ✅ 需求描述具体：如"60 岁以上老人需要掌握视频通话操作，目前 23% 会用，目标提升到 80%"

## 七、服务方案设计方法

### 7.1 服务方案四要素

每项需求对应 1 套解决方案，必须包含四要素：匹配专业能力 + 服务流程 + 工具 + 预期解决程度。

**示例（智能手机基础操作）**：
- 匹配专业能力：计算机/通信专业，熟悉 Android/iOS 系统操作
- 服务流程：现场调研老人手机型号 → 一对一教学（视频通话/扫码支付/拍照定位）→ 发放操作手册 → 加入答疑群
- 工具：操作手册 100 份（图文版，字号 18pt）+ 答疑微信群 1 个 + 录制视频 5 个（每个 3 分钟）
- 预期解决程度：参与培训的 60 位老人，80% 能独立完成视频通话，60% 能独立完成扫码支付

### 7.2 服务流程设计原则

**标准化 + 个性化**：
- 标准化：每场服务有固定流程（签到 → 集中讲解 15 分钟 → 一对一/小组操作 60 分钟 → 答疑 15 分钟 → 满意度反馈 5 分钟）
- 个性化：根据服务对象具体问题灵活调整（如老人不会扫码则加强扫码练习，村电商不会开店则手把手开店）

**服务流程四阶段**：
1. 前置沟通：服务前 3 天与当地对接人确认场地、设备、对象人数
2. 现场服务：按标准化流程开展，留照片 + 视频 + 签到表
3. 服务归档：填写服务记录单（含服务对象姓名/问题/解决方案/满意度）
4. 后续跟踪：服务后 7 天内电话回访，30 天内现场回访

### 7.3 解决方案设计

**解决方案 vs 服务流程的区别**：服务流程是"怎么做"，解决方案是"做到什么程度 + 留下什么"。

**解决方案三要素**：
1. 即时解决：现场解决问题（如修好电脑、教会视频通话）
2. 持续可用：留下工具与资料（操作手册、答疑群、视频回放）
3. 长效机制：建立持续帮扶（线上答疑、月度回访、季度现场）

**示例（电脑维修）**：
- 即时解决：现场修复 50 台电脑（系统重装 30 + 硬件更换 15 + 软件优化 5）
- 持续可用：发放"电脑维护手册"100 份 + 录制"常见故障处理"视频 10 个
- 长效机制：建立"XX 县电脑维修答疑群"，团队成员轮值，每月 1 次远程答疑，每季度 1 次现场回访

### 7.4 持续帮扶机制设计

**持续帮扶机制是科技服务类申报书的"加分项"**——评审看的是"项目结束后能不能持续"。

**四级持续机制**：
1. 线上答疑群：微信/QQ 群，团队成员轮值，2 小时内响应
2. 月度远程答疑：每月 1 次，团队视频连线服务对象，集中答疑
3. 季度现场回访：每季度 1 次，2~3 名队员赴地回访，重点解决疑难问题
4. 学年度接力：下一年度三下乡接力服务，形成长效机制

**示例**：建立"线上 + 线下"长效服务，每月 1 次远程答疑，每季度 1 次现场回访，每年暑期接力服务，形成"XX 县数字赋能"长效品牌。

**反例**：❌ "建立长效机制"——空话，无具体安排
**正例**：✅ "建立'XX 县数字赋能'答疑微信群，5 名团队成员轮值（每人每周 1 天），2 小时内响应；每月最后一个周末视频连线集中答疑；每季度 1 次现场回访（2~3 名队员赴地）；下一年度暑期接力服务。"

### 7.5 服务方案表格规范

| 需求 | 匹配专业能力 | 服务流程 | 预期解决方案 |
|------|--------------|----------|--------------|
| 智能手机基础操作 | 计算机/通信，熟悉 Android/iOS | 调研手机型号 → 一对一教学 → 发放手册 → 加答疑群 | 60 位老人 80% 独立完成视频通话 + 操作手册 100 份 + 答疑群 1 个 |
| 电脑故障维修 | 计算机，硬件/软件能力 | 检测故障 → 维修/重装 → 测试 → 填写维修单 | 修复 50 台（系统 30+硬件 15+优化 5）+ 维护手册 100 份 + 答疑群 1 个 |
| 电商开店基础 | 计算机/通信，电商知识（指导教师补充） | 平台选择 → 注册开店 → 商品上架 → 直播基础 | 帮助 20 户开店 + 录制教学视频 5 个 + 答疑群 1 个 |
| 网络反诈识别 | 计算机/通信 + 法律（指导教师补充） | 案例讲解 → 一对一答疑 → 安装反诈 App → 加群 | 200 人次培训 + 反诈单页 200 份 + 反诈 App 安装 150 部 |

### 7.6 不同子方向服务方案示例

**医疗服务子方向**（每项需求对应 1 套方案）：
- 慢病管理：临床医学，流程"血压/血糖测量 → 健康档案建立 → 用药指导 → 转诊建议"，预期"建立 100 份健康档案 + 用药指导 80 人次 + 转诊 5 人次"
- 急救知识：临床医学/护理，流程"理论讲解 → 假人示范 → 学员实操 → 考核发证"，预期"培训 60 人 + 80% 通过实操考核 + 急救手册 60 份"

**法律援助子方向**（每项需求对应 1 套方案）：
- 民法典婚姻家庭：法学，流程"案例讲解 → 一对一咨询 → 文书模板提供 → 转介律所"，预期"咨询 30 人次 + 模板发放 50 份 + 转介 3 件"
- 反诈与消费者权益：法学 + 计算机，流程"案例讲解 → App 安装 → 维权途径 → 答疑群"，预期"培训 200 人次 + 反诈 App 安装 150 部 + 维权指引单页 200 份"

**农业技术指导子方向**（每项需求对应 1 套方案）：
- 主导作物种植：农学，流程"田间诊断 → 技术讲解 → 示范操作 → 答疑群"，预期"诊断 30 块地 + 培训 50 户 + 种植技术手册 50 份"
- 养殖防疫：动物科学，流程"养殖场走访 → 防疫指导 → 疫苗使用 → 答疑群"，预期"走访 10 个养殖场 + 防疫指导 30 户 + 防疫手册 30 份"

### 7.7 服务方案评审要点

评审看服务方案时关注 4 点：
1. **匹配度**：匹配专业能力列是否真实对应团队成员专业背景
2. **流程性**：服务流程是否含"前置沟通 → 现场服务 → 服务归档 → 后续跟踪"四阶段
3. **可量化**：预期解决方案是否含即时解决（N 台/户/人）+ 持续可用（手册/视频/答疑群）+ 长效机制（月度/季度/年度）
4. **可持续性**：是否含持续帮扶机制四要素（线上答疑 + 月度远程 + 季度现场 + 年度接力）

**反例**：❌ "开展 IT 维修服务，帮助村民维修电脑"——无流程、无工具、无解决程度、无持续机制
**正例**：✅ "需求'电脑故障维修' → 匹配专业'计算机，硬件/软件能力' → 流程'检测故障 → 维修/重装 → 测试 → 填写维修单 → 加答疑群' → 解决方案'修复 50 台 + 维护手册 100 份 + 答疑群 1 个 + 月度远程答疑 + 季度现场回访'"

## 八、实施方案按服务场次列出方法

### 8.1 场次表 7 列结构

按场次实施安排表是科技服务类申报书的核心，评审第一眼看的就是这张表。

| 场次 | 日期 | 地点 | 服务对象 | 服务内容 | 人数 | 专业要求 |
|------|------|------|----------|----------|------|----------|
| 第 1 场 | 7.15 下午 | XX 镇 A 村文化礼堂 | A 村留守老人 40 人 | 智能手机基础操作（视频通话/扫码支付） | 40 | 计算机/通信，主讲 1 + 助教 2 |
| 第 2 场 | 7.16 上午 | XX 镇 A 村村委会 | A 村村民 30 人 | 电脑故障维修（系统重装/硬件更换） | 30 | 计算机，维修 2 + 记录 1 |
| 第 3 场 | 7.16 下午 | XX 镇 B 村电商服务站 | B 村村电商 20 人 | 电商开店与直播带货基础 | 20 | 计算机/通信，主讲 1 + 助教 2 |
| 第 4 场 | 7.17 上午 | XX 镇 B 村文化广场 | B 村村民 60 人 | 网络反诈识别 + 反诈 App 安装 | 60 | 计算机/通信 + 法律指导，主讲 2 |
| 第 5 场 | 7.17 下午 | XX 镇 C 村小学 | C 村村民 50 人 | 数字素养（政务 App/健康码使用） | 50 | 计算机/通信，主讲 1 + 助教 3 |
| 合计 | 5 场 | 3 个村 | — | IT 维修 + 电商培训 + 数字素养 + 反诈 | 200 人次 | — |

### 8.2 场次设计原则

**5~8 场为宜**：
- 场次太少（< 5 场）：覆盖不足，评审怀疑项目体量
- 场次太多（> 8 场）：奔波疲劳，单场质量下降

**单场人数控制**：
- 培训类：20~60 人（场地容量 + 一对一助教配比）
- 维修类：30 人/场（按 2 名维修员每小时维修 5 台计算，3 小时维修 30 台）
- 咨询类：1 对 1，每人 30 分钟，单场 6~10 人

**场次分布均衡**：
- 上午 + 下午各 1 场，避免疲劳
- 不同村轮流服务，避免单村集中
- 主力场次（高优先级需求）安排在前 3 天，弹性场次安排在后 2 天

### 8.3 场次表底部合计

必须含合计行：场次总数 × 单场人次 = 总服务人次。总服务人次必须与预期成果（八、）的"服务人次"完全一致。

**反例**：❌ 场次表合计 200 人次，预期成果写"覆盖 300 人次"——数据不一致，评审扣分
**正例**：✅ 场次表合计 200 人次（40+30+20+60+50），预期成果写"覆盖 200 人次（留守老人 40 + 村民 90 + 村电商 20 + 干部 50）"——数据完全对应

### 8.4 场次与团队分工对应

每场服务必须明确"专业要求"——主讲几人 + 助教几人 + 记录几人。5 人团队典型分工：
- 第 1 场（40 人培训）：主讲 1（张三）+ 助教 2（李四、王五）+ 记录 1（赵六）+ 后勤 1（钱七）
- 第 2 场（30 人维修）：维修 2（张三、李四）+ 记录 1（赵六）+ 后勤 2（王五、钱七）
- 第 3 场（20 人电商培训）：主讲 1（王五）+ 助教 2（赵六、钱七）+ 记录 1（张三）+ 后勤 1（李四）

**专业要求列**必须明确学科背景（如"计算机/通信"）+ 角色分工（主讲/助教/维修/记录/后勤）。

### 8.5 场次表设计模板

科技服务类场次表设计推荐按"3+2"模式：3 场主力服务（高优先级需求）+ 2 场辅助服务（中优先级需求）。

**5 场 200 人次模板**（科技服务子方向）：
- 第 1 场：A 村 智能手机基础操作 留守老人 40 人（高优先级）
- 第 2 场：A 村 电脑故障维修 村民 30 人/修复 50 台（高优先级）
- 第 3 场：B 村 网络反诈识别 + 反诈 App 安装 村民 60 人（高优先级）
- 第 4 场：B 村 电商开店与直播带货 村电商 20 人（中优先级）
- 第 5 场：C 村 数字素养培训 村民 50 人（中优先级）

**8 场 300 人次模板**（医疗 + 法律联合子方向）：
- 第 1~3 场：3 个村 慢病管理 + 健康体检 老年人 60+60+60=180 人
- 第 4~5 场：2 个村 急救知识培训 村民 30+30=60 人
- 第 6~8 场：3 个村 民法典婚姻家庭 + 反诈咨询 村民 20+20+20=60 人

### 8.6 场次表常见错误

- ❌ 场次表 3 列（日期/地点/工作）：评审看不到对象、人数、专业要求
- ✅ 场次表 7 列（场次/日期/地点/服务对象/服务内容/人数/专业要求）：评审一目了然

- ❌ 场次表无合计行：评审要自己算人次
- ✅ 场次表底部合计行：5 场 × 200 人次（留守老人 40 + 村民 90 + 村电商 20 + 干部 50）

- ❌ 场次表所有场次都安排在同一村：覆盖不足
- ✅ 场次表分布在 3 个村：覆盖均衡，且每村至少 1 场

- ❌ 场次表"专业要求"列空着或只写"团队全员"：评审无法判断专业匹配
- ✅ 场次表"专业要求"列写"计算机/通信，主讲 1+助教 2"：评审可判断匹配度

## 九、评审标准与打分维度

科技服务类评审五维打分，总分 100。

### 9.1 五维评分

| 维度 | 权重 | 评分要点 | 高分标准 | 低分表现 |
|------|------|----------|----------|----------|
| 专业性 | 30% | 团队专业与服务内容匹配 + 服务流程规范 + 解决方案专业 | 计算机 3+通信 2 团队修电脑教电商，指导教师随队，方案含工具+流程+解决程度 | 团队无相关专业成员硬上，方案只有"开展服务"无流程 |
| 需求匹配度 | 25% | 需求来源真实 + 优先级合理 + 需求与场次对应 | 需求清单来自当地委托函 + 5 项需求按紧迫程度排序 + 每项高优先级需求有对应场次 | 需求"拍脑袋"想出来，无优先级，场次与需求脱节 |
| 可持续性 | 20% | 持续帮扶机制可行 + 资料留存 + 学年度接力 | 线上答疑群+月度远程+季度现场+年度接力，留下操作手册+视频回放 | "建立长效机制"空话，无具体安排 |
| 安全性 | 15% | 安全预案齐全 + 保险购买 + 服务类专属安全 | 5 段安全预案 + 全员短期意外险 + 维修断电规范 | 只有"注意安全"一句话 |
| 传播力 | 10% | 宣传计划 + 媒体覆盖 + 短视频产出 | 中青网+校团委+抖音+B站全覆盖，3 个时间节点发布 | 无宣传计划 |

### 9.2 评分计算示例

**高分案例**（85 分）：
- 专业性 27/30：计算机 3+通信 2 团队修电脑教电商，指导教师随队，方案含工具+流程+解决程度
- 需求匹配 22/25：需求来自当地团委委托函，5 项需求按紧迫程度排序，5 场次对应 5 项需求
- 可持续性 17/20：线上答疑群+月度远程+季度现场+年度接力，操作手册 100 份+视频回放 5 个
- 安全性 14/15：5 段安全预案 + 全员短期意外险 + 维修断电规范 + 工具绝缘
- 传播力 5/10：中青网 1+校团委 2+抖音 3，3 个时间节点发布（部分媒体未确认）

**低分案例**（45 分）：
- 专业性 15/30：团队 5 人无相关专业背景（全是文科），硬上 IT 维修
- 需求匹配 10/25：需求"想当然"，无优先级，场次与需求不对应
- 可持续性 5/20：只有"建立长效机制"一句话
- 安全性 10/15：有保险但无服务类专属安全
- 传播力 5/10：有宣传计划但无中青网

### 9.3 一票否决项

- 安全预案不达标（无保险 / 无应急联系人 / 无应急流程）→ 直接淘汰
- 团队专业与服务内容严重不匹配（如文科团队做 IT 维修）→ 直接淘汰
- 需求清单与场次表严重脱节（场次服务内容不在需求清单内）→ 直接淘汰
- 预期成果写"若干""一定""相关"等模糊词 → 退回重写

### 9.4 评审流程

校级初审（团委）→ 学院复审（学院团委 + 指导教师）→ 学校终审（校团委 + 专家组）。初审筛格式，复审筛内容，终审筛质量。3 级评审均通过方可立项。

## 十、避坑指南与正反例

科技服务类高频踩坑 10 例，每例含反例 + 正例 + 要点。

**坑 1：服务内容与团队专业不匹配**

❌ 反例：团队 5 人全是历史专业，申报"IT 维修 + 电商培训"科技服务
✅ 正例：团队 5 人含计算机 3 + 通信 2，申报"IT 维修 + 电商培训 + 数字素养"科技服务
要点：科技服务类必须专业匹配，文科团队可申报法律援助或政策宣讲

**坑 2：需求清单"想当然"**

❌ 反例：未做预调研，凭印象写"村民需要电商培训"
✅ 正例：实地预调研 2 天，访谈村干部 5 人 + 村民 20 人，梳理出 5 项需求并按紧迫程度排序
要点：需求必须有来源（团委反馈/预调研/委托函），不能"拍脑袋"

**坑 3：场次表用"前期/中期/后期"**

❌ 反例：前期开展 IT 维修，中期开展电商培训，后期开展数字素养
✅ 正例：7.15 下午 A 村智能手机 40 人；7.16 上午 A 村电脑维修 30 人；7.16 下午 B 村电商 20 人
要点：场次表必须按"日"为粒度，每行含场次/日期/地点/对象/内容/人数/专业要求 7 列

**坑 4：服务方案只有"开展服务"无流程**

❌ 反例：服务方案：开展 IT 维修服务，帮助村民维修电脑
✅ 正例：服务方案：检测故障 → 维修/重装 → 测试 → 填写维修单 → 加入答疑群；预期修复 50 台（系统 30+硬件 15+优化 5）
要点：服务方案必须含 4 列（需求/匹配能力/服务流程/预期解决方案）

**坑 5：无持续帮扶机制**

❌ 反例：建立长效机制，扩大项目影响
✅ 正例：建立"XX 县数字赋能"答疑微信群，5 名成员轮值（每人每周 1 天），2 小时响应；每月视频连线集中答疑；每季度现场回访；下一年度暑期接力
要点：持续帮扶机制含四级（线上答疑+月度远程+季度现场+年度接力），每级有具体安排

**坑 6：预期成果写"若干"**

❌ 反例：服务若干人次，取得良好效果，扩大影响
✅ 正例：服务 5 场 × 200 人次（留守老人 40+村民 90+村电商 20+干部 50），修复电脑 50 台，发放手册 100 份，建立答疑群 1 个
要点：所有成果必须可量化，禁止"若干""一定""相关"

**坑 7：安全预案只有"注意安全"**

❌ 反例：团队将严格遵守安全规定，注意人身、财产安全
✅ 正例：5 段安全预案（出行/人身/应急联系人/应急流程/保险）+ 服务类专属安全（维修断电操作、工具绝缘、防静电）
要点：服务类必须含专属安全（维修带电作业/医疗消毒/法律免责声明）

**坑 8：经费全是整数**

❌ 反例：交通费 3000 元，食宿费 5000 元，物资费 2000 元，合计 10000 元
✅ 正例：交通费 2860 元（高铁 130×5×2 + 包车 300×4），食宿费 3920 元（招待所 120×3×7 + 餐费 40×5×7），物资费 1500 元（U 盘 50×20+维修工具 400+培训手册 100×6）
要点：每项金额非整数 + 计算依据含单价×数量

**坑 9：物资费占比过低**

❌ 反例：物资费 200 元（占预算 2%）——评审怀疑没准备实物
✅ 正例：物资费 1500 元（占预算 30%）——U 盘 + 维修工具 + 培训手册 + 反诈单页 + 小礼品
要点：科技服务类物资费占比 30~40%

**坑 10：场次表与预期成果数据不一致**

❌ 反例：场次表合计 200 人次，预期成果写"覆盖 300 人次"
✅ 正例：场次表合计 200 人次（40+30+20+60+50），预期成果"覆盖 200 人次（留守老人 40+村民 90+村电商 20+干部 50）"
要点：场次表合计 = 预期成果人次 = 服务记录归档数，三者必须完全一致

**坑 11：团队成员专业与服务内容脱节**

❌ 反例：5 人团队全是文学专业，申报"IT 维修 + 数字素养培训"
✅ 正例：5 人团队含计算机 3 + 通信 2，申报"IT 维修 + 数字素养 + 电商培训"
要点：团队专业必须覆盖 ≥ 60% 服务内容，低匹配项由指导教师补强

**坑 12：服务流程无前置沟通与后续跟踪**

❌ 反例：服务流程：检测故障 → 维修 → 测试（缺前置与跟踪）
✅ 正例：服务流程：前置沟通（服务前 3 天确认场地）→ 现场服务 → 服务归档 → 后续跟踪（7 天电话回访 + 30 天现场回访）
要点：服务流程必须含"前置 → 现场 → 归档 → 跟踪"四阶段

**坑 13：服务子方向与团队学科背景不符**

❌ 反例：计算机学院团队申报"医疗服务 + 法律援助"
✅ 正例：计算机学院团队申报"科技服务（IT 维修 + 电商培训）"，跨学院联合申报医疗/法律
要点：服务子方向必须与团队学科背景匹配，跨学科可联合申报

**坑 14：持续帮扶机制无落地点**

❌ 反例：建立长效机制，扩大项目影响（空话）
✅ 正例：建立"XX 县数字赋能"答疑微信群，5 名成员轮值，2 小时响应；每月视频连线集中答疑；每季度现场回访；下一年度暑期接力
要点：持续帮扶机制每级都要有具体安排（人/时间/方式）

**坑 15：物资清单与方案脱节**

❌ 反例：服务方案含"操作手册 100 份"，物资清单只列"印刷费 200 元"
✅ 正例：服务方案含"操作手册 100 份"，物资清单含"操作手册 100 份 × 3 元 = 300 元"
要点：物资清单必须与服务方案一一对应，金额可追溯

## 十三、学校差异处理

### 13.1 模板差异

不同学校下发的三下乡立项申报书模板在栏目顺序、字数要求上有微调。**优先用学校下发的模板填**，本 skill 的内容作为质量参考。

### 13.2 常见学校差异速查

| 学校类型 | 栏目差异 | 字数差异 | 经费上限 |
|----------|----------|----------|----------|
| 985/211 | 11 栏目齐全 | 总字数 6000~8000 | 1.5~2 万 |
| 普通本科 | 11 栏目齐全 | 总字数 4500~6500 | 0.8~1.5 万 |
| 高职高专 | 9~10 栏目（合并签字栏） | 总字数 3000~5000 | 0.5~1 万 |

### 13.3 团中央专项报送

部分学校要求三下乡项目对接团中央专项（如"数字乡村""健康中国""法治乡村"）。若项目对接专项，在申报书末尾追加"附：团中央专项报送说明"，注明对应专项、契合度、预期形成优秀案例数。

### 13.4 跨学院组队

科技服务类建议跨学院组队（如计算机学院 + 法学院联合申报"IT 维修 + 反诈咨询"）。跨学院组队需在团队成员信息表注明"队长所在学院为申报单位，其他成员所在学院为协作单位"。

### 13.5 持续帮扶机制跨年度接力

部分学校要求持续帮扶机制含"跨年度接力"安排（即下一年度三下乡接力服务）。需在服务方案"持续帮扶机制"小节明确接力团队组建方式（如"由本届队长对接下届队长，9 月前完成交接"）。
