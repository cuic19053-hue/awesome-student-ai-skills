# 三、信息采集清单

> 从 `subskills/tech-service/SKILL.md` 外移而来（渐进式披露）。
> 何时阅读：需要逐条向用户提问采集信息时。

### 3.1 通用必采（10 字段）

| 字段 | 说明 | 示例 |
|------|------|------|
| 团队名称 | 含"赴+地点+主题+服务团" | 赴 XX 县数字赋能科技服务团 |
| 实践主题 | 团中央年度主题 | 乡村振兴 青春建功 |
| 实践地点 | 精确到村/社区 | XX 省 XX 县 XX 镇 3 个行政村 |
| 实践时间 | 含出发返程 | 2025.07.15-07.21（7 天） |
| 团队人数 | 5~12 人为佳（小而精） | 5 人 |
| 队长信息 | 姓名/学号/专业/年级/电话 | 张三/202212345/计算机 2022 级/大三/138XXXXXXXX |
| 指导教师 | 姓名/职称/电话/是否随队 | 李教授/副教授/139XXXXXXXX/随队 |
| 申报单位 | 学院全称 | 计算机科学与技术学院 |
| 申报日期 | 中文格式 | 2025 年 5 月 20 日 |
| 成员信息 | 每人 5 字段 | 姓名/学号/专业/分工/电话 |

### 3.2 科技服务类专属必采（12 字段）

**A. 服务子方向与对象**
1. 服务子方向：科技/医疗/法律/农业四选一（可主+辅，主方向占比 ≥ 70%）
2. 服务对象类型：村民/留守老人/种养殖大户/村电商/村干部/外出务工人员（多选）
3. 服务对象规模：单场 20~60 人，总覆盖 150~300 人次
4. 服务对象需求来源：当地团委反馈 / 实地预调研 / 政府部门委托函

**B. 需求与方案**
5. 服务对象需求清单：3~6 项核心需求（如"智能手机使用 + 电商开店 + 反诈 + 视频通话"）
6. 需求优先级排序：高/中/低（按需求紧迫程度 + 团队能力匹配度综合排序）
7. 团队专业能力匹配矩阵：每项需求 × 团队成员专业 → 匹配度评估
8. 解决方案设计：每项需求对应 1 套方案（服务流程 + 工具 + 预期解决程度）

**C. 场次与产出**
9. 服务场次：5~8 场为宜，单场 20~60 人，总覆盖 150~300 人次
10. 单场时长：60~180 分钟（培训类 90~120 分钟、维修类 60~180 分钟、咨询类 30~60 分钟/人）
11. 服务记录方式：签到表 + 服务记录单 + 满意度反馈表 + 解决方案手册
12. 持续帮扶机制：线上答疑群 + 月度回访 + 季度现场服务 + 学年度长效接力

### 3.3 保障与经费

| 类别 | 必采字段 | 示例 |
|------|----------|------|
| 安全 | 应急联系人 3 名、应急流程分级、保险购买情况 | 平安短期意外险 30 万保额 |
| 宣传 | 校内/校外/新媒体三类平台 + 发布篇数 | 中青网 1 + 校团委 2 + 抖音 3 |
| 预算 | 交通/食宿/物资/印刷/其他 5 项 + 金额 + 计算依据 | 物资 1500 元 = U 盘 50×20 + 维修工具 400 + 培训手册 100×6 |
| 物资清单 | 维修工具/培训手册/反诈单页/小礼品 | 维修工具包 5 套 + 培训手册 100 份 + 反诈单页 200 份 |

### 3.4 字段优先级

| 优先级 | 字段 | 缺失影响 |
|--------|------|----------|
| P0 必填 | 团队名称/主题/地点/时间/队长/指导教师/服务子方向/需求清单/专业能力匹配 | 申报书退回重填 |
| P1 重要 | 团队人数/成员分工/按场次表/服务方案/安全预案/预期成果/持续帮扶机制 | 评审扣大分 |
| P2 推荐 | 经费计算依据/宣传计划/学校审批/团中央专项报送 | 评审加分项 |

### 3.5 追问话术

**子方向相关**：
- 用户说"做三下乡服务"→ 追问"四类子方向选哪类？科技服务/医疗服务/法律援助/农业技术指导？"
- 用户说"科技服务"→ 追问"具体做哪些？IT 维修/电商培训/数字素养/反诈宣讲？"
- 用户说"我们都是计算机专业"→ 追问"匹配哪些需求？智能手机/电脑维修/办公软件/电商开店？"

**需求与对象相关**：
- 用户说"村民需要"→ 追问"需求是哪儿来的？当地团委反馈？实地预调研？政府部门委托函？"
- 用户说"教村民用手机"→ 追问"具体哪几个场景？微信视频/扫码支付/反诈识别/拍照定位？"
- 用户说"覆盖村里人"→ 追问"具体哪几类？留守老人/种养殖大户/村电商/村干部？每类预计多少人次？"

**专业匹配相关**：
- 用户说"我们团队能修电脑"→ 追问"团队成员具体什么专业？硬件维修能力还是软件维护能力？是否需要指导教师补充？"
- 用户说"我们指导老师是医学教授"→ 追问"老师能全程随队吗？医疗服务是否需要医师执业资格证？是否需要与当地卫生院联合开展？"
- 用户说"法律援助"→ 追问"团队成员是否有法考经验？指导老师是否执业律师？是否能出具书面法律意见？"

**场次与产出相关**：
- 用户说"5 场服务"→ 追问"每场日期 + 地点 + 对象 + 服务内容 + 人数 + 专业要求？能不能列成表？"
- 用户说"维修 50 台电脑"→ 追问"维修记录单怎么存档？故障分类统计？是否提供 30 天质保？"
- 用户说"培训村民"→ 追问"培训手册印多少份？是否录视频供回看？后续线上答疑怎么组织？"

### 3.6 采集纪律

1. 分批提问：先采 P0 通用 10 字段，再采 P0 服务专属 8 字段，最后采 P1/P2
2. 不替用户编：拿不准的事实，让用户去查证后再填（如指导教师职称、保单号、当地委托函）
3. 保留原话：用户口述的经历可保留原意但用书面语整理，不要过度升华
4. 复述确认：信息采完后，按 11 栏目顺序复述给用户确认，再进入撰写阶段
5. 专业匹配校对：采集完成后单独校对一遍团队成员专业与服务内容的匹配度（详见 §七）
