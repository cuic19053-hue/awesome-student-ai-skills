# 互联网+大学生创新创业大赛商业计划书 Skill v2.1

本 skill 处理"互联网+大学生创新创业大赛"（即"中国国际大学生创新大赛"）商业计划书（BP）全流程：信息采集 → 11 大栏目撰写 → 案例化 11 项必加章节填充 → docx 生成 → 质检。仅处理商业计划书型（非学术作品、非调研报告、非论文）；与挑战杯创业计划赛道、大创创业训练差异见第十九章。

**【核心训练声明】**：本 Skill 已深度学习近 3 届互联网+全国金奖商业计划书。AI 输出时必须严格强调“痛点真实性”、“商业壁垒（护城河）”、“财务模型合理性”及“带动就业指标”，杜绝空洞的商业幻想，全面对齐国金项目的评审逻辑。

**输出文件**：可提交的 .docx（A4 纸张，宋体小四正文，黑体三号标题，1.5 倍行距，首行缩进 2 字符，含商业模式画布 9 宫格、5 年财务三表、社会经济效益量化表、4 维度评审对应章节、技术路线图说明）。

**2025 起评审维度变化**：往年"创新性 + 商业性 + 团队 + 社会价值"四维，2025 起改为**个人成长 30% + 项目创新 30% + 产业价值 25% + 团队协作 15%**，最显著变化是"个人成长"权重 30% 跃居首位——BP 必须突出"学生本人学到了什么、改变了什么"，不只是项目本身；同时"项目创新"30% 要求 BP 必须有**技术深度**支撑（科学挑战、算法对比、技术路线、数学公式），而非纯商业描述。

**v2.1 升级要点（基于真实案例 case2 优化）**：
1. 新增国家政策引用规范（10+ 文件，按时间倒序，含发文机关+文号+标题+时间+关键表述）
2. 新增科学挑战 3 段结构（数据→算法→系统 / 感知→认知→决策层层递进）
3. 新增国内外研究现状综述（30+ 文献，英文 ≥60%，含 SCI 一区/二区）
4. 新增算法对比表（≥3 维度对比 + 选型结论）
5. 新增 3 张技术路线图（研究内容关系图 + 研究方法图 + 技术路线图）
6. 新增数学公式规范（每个核心算法含公式+变量定义+编号）
7. 新增社会经济效益量化（12 项指标，传统 vs 系统 4 列对比）
8. 新增 4 维度评审对应章节（个人成长 3 段/项目创新 3 套/产业价值 4 维度/团队协作 4 维度）
9. 新增完整商业部分（4P + 3C + SWOT + 5 年三表）
10. 新增实践过程章节 + 技术壁垒章节
11. 新增 JSON Schema + build.py 接口 + 3 档字数版本 + 质检清单

**重要纠偏**：v1.x 版本"坑 10：把学术研究内容混入 BP"是错误指导。案例 case2（已获省赛金奖）证明：2025 互联网+ "项目创新 30%"维度必须有技术深度支撑，BP 含科学挑战、文献综述、算法对比、技术路线、数学公式不是"学术内容混入"，而是"项目创新 30%"维度的核心得分点。但需注意：技术内容必须服务商业叙事，不能写成纯学术论文。

## 一、适用场景与触发条件

**适用**：用户提到"互联网+""互联网+大赛""高教主赛道""红色之旅""职教赛道""互联网+商业计划书""中国国际大学生创新大赛"等关键词，且需提交"商业计划书"形态文档（非学术论文、非调研报告）。

**不适用**（走其他 skill）：
- 挑战杯课外学术科技作品（论文/调查报告/发明实物）→ 走挑战杯 skill
- 大创-创业训练项目（教学项目，非参赛）→ 走创业训练 skill
- 大创-创业实践（已注册公司但非参赛）→ 走创业实践 skill
- 创青春创业大赛（团中央主办）→ 走创业训练 skill（结构相近）

**三大赛道区分**：

| 赛道 | 适用对象 | 评审侧重 | 特色要求 |
|------|----------|----------|----------|
| 高教主赛道 | 本科生/研究生 | 创新 + 商业 + 成长 | 项目创新性与商业化潜力，含技术深度 |
| 红色之旅 | 全体在校生 | 红色基因 + 乡村振兴 | 必含老区/乡村帮扶成效 + 红色教育 |
| 职教赛道 | 高职/中职生 | 技能 + 就业 + 落地 | 强调技术技能与岗位对接 |

**触发后第一步**：先确认赛道（三选一）。用户未明确时问"你报哪个赛道？高教主赛道/红色之旅/职教赛道，分别对应本科生、红色主题、职教生"。赛道确认后才能定调。

**触发后第二步**：确认项目是否含技术深度（算法/硬件/系统）。如含技术，必须启用第 5~10 章（国家政策/科学挑战/文献综述/算法对比/技术路线/数学公式）；如纯商业模式创新项目（如纯互联网产品），可省略数学公式章节，但其他必加。

## 二、工作流程总览

六阶段串行执行，每阶段完成后再进入下一阶段：

**阶段 1 信息采集（15~22 轮对话）**：按"通用必采 → 赛道专属 → 项目/市场/产品 → 商业模式 → 运营现状 → 财务预测 → 融资计划 → 团队 → 风险 → 个人成长素材 → 政策文件 → 技术深度（科学挑战/文献/算法/公式）→ 实践过程 → 技术壁垒 → 社会效益"顺序采集。每轮不超过 5 个字段。商业字段（TAM/SAM/SOM、CAC/LTV、定价、毛利率）+ 政策文件 + 技术深度字段缺失必须追问，禁止编造市场数据、政策文件名、文献引用。

**阶段 2 内容撰写（一次性产出）**：按 11 大栏目顺序撰写。执行摘要 500~800 字为最重要栏目，必须含六要素。商业模式画布必须 9 要素齐全。5 年财务三表必须完整。个人成长段落必须用第一人称写出"我学到了什么/我改变了什么"。技术深度项目必须含科学挑战 3 段 + 文献综述 30+ 篇 + 算法对比 + 3 张技术路线图 + 数学公式。

**阶段 3 案例化章节填充**：按第 5~14 章 11 项案例化必加章节逐项填充。国家政策 10+ 按时间倒序；科学挑战 3 段层层递进；文献综述 30+ 篇含 SCI 一区/二区；算法对比表 ≥3 维度；技术路线图 3 张含图号标题；数学公式编号+变量定义；社会经济效益 12 项 4 列对比；4 维度评审对应章节按权重排序；完整商业部分 4P+3C+SWOT+5 年三表；实践过程含照片说明；技术壁垒含专利+检测报告。

**阶段 4 docx 生成**：调用 `python build.py --data data.json --out output.docx` 生成 Word 文档。data.json 字段定义见第十六章 JSON Schema。

**阶段 5 质检**：按第十八章 30 项清单逐项检查。任一项不达标返回阶段 2 修改。重点核查执行摘要六要素、商业模式画布 9 宫格、5 年财务三表、个人成长段落、4 维度评审对应度、政策文件数量与时间倒序、文献数量与英文占比、算法对比维度数、技术路线图数量、社会效益指标数。

**阶段 6 提交**：30 项全过 → 可提交。提交前再目测 docx 格式（字体、行距、缩进、表格、页边距、页码）。

**禁止行为**：
- 跳过采集直接套模板
- 编造市场规模、用户数、营收、融资额、政策文件名、文献引用、专利号
- 用"前景广阔""意义重大""颠覆性""赋能""闭环"等空话
- 把纯学术研究内容（无商业落地的纯理论）混入 BP
- 个人成长只写"提升了能力"不写"从 X 变为 Y"具体变化
- 商业模式画布少要素（必须 9 个齐全）
- 团队成员超 15 人（互联网+上限）
- 政策文件只列文件名不摘录关键表述
- 文献综述只列 5~10 篇（必须 30+）
- 算法对比无选型结论
- 技术路线图无图号标题
- 数学公式无变量定义
- 社会效益指标少于 10 项
- 财务三表不满足会计恒等式（资产=负债+所有者权益）

| group | 组别 | 本科生组/研究生组/高职组 | "赛道内组别？" |
| leader_name | 负责人姓名 | 张三 | "项目负责人全名？" |
| leader_id | 负责人学号 | 202212345 | "学号？" |
| leader_major | 负责人专业 | 工商管理 | "专业全称？" |
| leader_grade | 负责人年级 | 2022 级 大三 | "入学年份与年级？" |
| leader_phone | 联系电话 | 138XXXXXXXX | "手机号？" |
| college | 学院全称 | 工商管理学院 | "学院全称？" |
| school | 学校全称 | XX 大学 | "学校全称？" |

| advisor_name | 指导教师姓名 | 李教授 | "指导教师全名？建议有创业/投资背景" |

### 3.2 项目核心（10 字段）

| 字段 | 说明 | 示例 |
|------|------|------|
| one_liner | 项目一句话 | "为高校在校生解决闲置流转低效，通过 LBS 同校面交实现信任交易" |
| industry | 所属行业 | 互联网/二手交易 |
| target_user | 目标用户 | 高校 18~24 岁在校生 |
| pain_point | 用户痛点 | 跨城交易邮费高、面交难、信任度低 |
| stage | 项目阶段 | 创意/种子/MVP/早期运营/成长期 |
| registered | 是否注册公司 | 否（创意/种子期）/ 是（含公司名+时间） |
| revenue | 当前营收 | 0 / 12 万元/年 |
| users | 当前用户数 | 0 / 注册 5000 / 月活 1500 |
| ip_status | 知识产权 | 软著 1 项/专利申请中/无 |
| partnerships | 合作 | 3 家高校社团 / 5 家校企 / 无 |

### 3.3 市场分析素材

- 行业规模数据（TAM 总市场容量，需权威来源：艾瑞/IDC/国家统计局/白皮书）
- 可服务市场 SAM（按地域/人群/场景切分）
- 可获取市场 SOM（项目 1~3 年实际可拿份额，SAM 的 1%~10%）
- 3~5 个直接竞品 + 2~3 个间接竞品，每个含：名称/定位/用户规模/融资阶段/优劣势
- 用户调研记录（建议访谈 10+ 用户，记录痛点/付费意愿/价格敏感度）

### 3.4 商业模式素材

- 商业模式画布 9 要素：客户细分/价值主张/渠道通路/客户关系/收入来源/核心资源/关键业务/重要伙伴/成本结构
- 盈利模式：抽佣/订阅/增值/广告/数据/SaaS，至少 1 类清晰
- 定价策略：单次/月度/年度价格，对照竞品与付费意愿
- CAC 估算 = 推广预算 / 新增用户数
- LTV 估算 = 客单价 × 复购次数 × 毛利率

### 3.5 运营现状素材

- 已取得成绩：用户数、营收、合作客户、签约订单
- 团队架构：核心成员分工、外部顾问
- 关键里程碑：MVP 上线时间、首批用户、首笔营收、首个合作
- 关键指标 KPI：北极星指标 + 次级指标（注册转化/留存/复购/付费率）
- 红色之旅赛道额外采集：帮扶老区/乡村名称、带动农户数、增收数据

### 3.6 财务与融资素材

- 5 年营收预测（按月或季度，Year1 细 Year5 粗）
- 5 年成本结构（固定：人员/服务器/办公；变动：获客/履约/客服）
- 毛利率估算（行业平均 + 项目实际）
- 盈亏平衡点（用户数/月营收达到多少时不再亏损）
- 本轮融资需求：金额、估值、出让股权、资金用途分配
- 5 年三表：利润表/现金流量表/资产负债表

### 3.7 团队素材（每人 5 字段）

姓名/学号/专业年级/职务分工/相关经历（实习/项目/获奖）。核心成员 3~8 人，总团队≤15 人。建议商科 + 技术 + 设计 + 运营复合，纯商科或纯技术团队扣分。指导教师 1~2 名，写明职称/研究方向/指导创业经历。

### 3.8 个人成长素材（2025 评审 30% 维度）

- 你在项目中承担的具体角色与动作
- 你从 XX 状态变为 YY 状态（如"从不理解 CAC 到独立完成 LTV/CAC 模型"）
- 你学到的硬技能（市场测算/财务建模/产品原型）+ 软技能（沟通/协调/抗压）
- 你失败过的事 + 复盘收获
- 你在团队协作中解决的冲突

### 3.9 国家政策文件素材（新增）

- 政策文件 10+ 篇，覆盖近 5 年
- 每篇含：发文机关 + 文号 + 标题 + 时间 + 与项目相关的关键表述摘录
- 必须按时间倒序排列（最新在前）
- 必须含最高领导人讲话（如适用，如习近平总书记关于创新创业/应急救援/乡村振兴的讲话）
- 时序跨度建议 5 年以上

### 3.10 技术深度素材（新增，技术型项目必采）

- 3 个科学挑战（层层递进：数据→算法→系统 / 感知→认知→决策）
- 30+ 篇国内外研究现状文献（英文 ≥60%，含 SCI 一区/二区）
- 算法对比表（≥3 维度，含选型结论）
- 3 张技术路线图（研究内容关系图 + 研究方法图 + 技术路线图）
- 数学公式（每个核心算法含公式+变量定义+编号）
- 算法流程图（用文字描述流程）

### 3.11 实践过程素材（新增）

- 团队学习照片说明（≥5 张，含图号+说明文字）
- 企业考察照片说明
- 实物制作/试飞验证照片说明
- 合作协议（≥3 家企业/单位，含合作内容）

### 3.12 技术壁垒素材（新增）

- 已申请/已授权专利（≥1 项，含专利号+名称）
- 软件检测报告
- 系统/实物验证截图说明
- 知识产权清单

### 3.13 社会经济效益素材（新增）

- 12 项量化指标，每项含：指标名/传统模式基准/系统模式预期/提升幅度
- 4 维度产业价值：市场规模/就业带动/税收贡献/社会效益
- 4 维度团队协作：分工/互补/共识/危机处理
- 3 套项目创新点：技术/模式/业态

### 3.14 字段优先级与追问

| 优先级 | 字段 | 缺失影响 |
|--------|------|----------|
| P0 必填 | project_name/track/leader_name/college/school/advisor_name | 无法生成 BP |
| P0 必填 | one_liner/industry/target_user/pain_point | 执行摘要无法撰写 |
| P0 必填 | executive_summary/market_analysis/business_model/financial_forecast | 核心栏目空白 |
| P0 必填 | personal_growth | 2025 评审 30% 维度失分 |
| P0 必填 | policy_citations/scientific_challenges/literature_review | 项目创新 30% 维度失分 |
| P0 必填 | economic_benefits/industry_value | 产业价值 25% 维度失分 |
| P0 必填 | team_collaboration | 团队协作 15% 维度失分 |
| P1 强烈建议 | team_members/competitors/canvas/risks | 评审大扣分 |
| P1 强烈建议 | algorithm_comparison/tech_roadmap/formulas | 技术深度不足 |
| P1 强烈建议 | marketing_4p/pricing_3c/financial_statements | 商业部分不完整 |

```
基于上表对比分析，本项目选用 SAC 算法，理由如下：
1. 火场环境为连续动态空间，需要连续动作输出，DQN 离散动作不适用；
2. 火场环境具有高不确定性，需要强探索能力，DDPG 探索能力不足；
3. SAC 算法基于最大熵原理，平衡探索与利用，且在动态环境中表现稳定；
4. 虽 SAC 计算复杂度高，但本项目通过边缘计算单元 + 模型压缩技术可满足实时性要求。

参考文献：[15][16][17]
```

### 10.3 公式撰写模板

```
（1）ASCN 算法

ASCN（Adaptive Spatial Clustering Network）是本项目提出的自适应空间聚类
网络，用于多模态点云数据融合。核心公式如下：

密度计算公式：
  ρ(p) = |N(p, r)| / V(r)                              式(1)

其中 N(p, r) 表示以点 p 为中心、半径为 r 的邻域内的点集，V(r) 为该邻域球
体积，ρ(p) 为点 p 处的局部密度。

动态扩张率：
  δ = δ_min + (δ_max - δ_min) · (1 - ρ̂)               式(2)

其中 ρ̂ 为归一化密度值，δ_max 和 δ_min 分别为扩张率的上下界。当密度高时
（ρ̂ → 1），扩张率趋近 δ_min（保守扩张）；当密度低时（ρ̂ → 0），扩张率
趋近 δ_max（积极扩张）。

算法流程：
Step 1：输入多模态点云 P = {p_1, p_2, ..., p_n}
Step 2：对每个点 p_i，计算密度 ρ(p_i)（式 1）
Step 3：归一化密度得 ρ̂(p_i)
Step 4：计算动态扩张率 δ_i（式 2）
Step 5：基于 δ_i 进行邻域扩张聚类
Step 6：输出聚类结果 C = {C_1, C_2, ..., C_m}

核心创新点：
1. 引入动态扩张率，自适应不同密度区域；
2. 多模态信息融合，提升聚类稳定性；
3. 时间复杂度 O(n log n)，满足实时性要求。
```

**贝叶斯估计**：P(A|B) = P(B|A)·P(A) / P(B)

| 产业价值 | 25% | §4.7 + §11 + §12.3 | 4 维度（市场/就业/税收/社会）|
| 团队协作 | 15% | §4.9 + §12.4 | 4 维度（分工/互补/共识/危机）|

### 12.6 4 维度评分计算示例

假设 3 位评审专家打分：

| 维度 | 权重 | 专家 A | 专家 B | 专家 C | 平均 | 加权得分 |
|------|------|--------|--------|--------|------|----------|
| 个人成长 | 30% | 85 | 80 | 88 | 84.3 | 25.3 |
| 项目创新 | 30% | 80 | 75 | 85 | 80.0 | 24.0 |
| 产业价值 | 25% | 85 | 85 | 80 | 83.3 | 20.8 |
| 团队协作 | 15% | 90 | 85 | 90 | 88.3 | 13.3 |
| 合计 | 100% | - | - | - | - | 83.4 |

最终 83.4 分。省赛铜奖线通常 75+，银奖 80+，金奖 85+；国赛金奖 88+。省赛晋级后国赛需重新打磨 BP，重点补强"项目创新"和"产业价值"维度（国赛要求更高量化数据）。

### 12.7 提分策略

按权重排序：
- 个人成长（30%）：第一人称撰写，必含"从 X 变 Y" + 1 个失败复盘 + 3 段结构
- 项目创新（30%）：技术/模式/业态 3 套创新点 + 量化提升数据 + MVP 验证
- 产业价值（25%）：市场规模 + 就业带动 + 税收贡献 + 社会效益 4 维度 + 5 年财务
- 团队协作（15%）：复合背景表 + 分工机制 + 共识机制 + 危机处理案例

前两维占 60%，必须双 80+ 才有省赛银奖希望。任一维度 < 60 分直接淘汰。

**提分优先级**：先把个人成长写到 80+（最易拿分，多数 BP 失分在此）；再打磨项目创新 3 套；最后补全产业价值与团队协作。

### 13.1 4P 营销组合

### 13.2 3C 定价模型

3C 框架：Cost（成本）/ Competitor（竞争）/ Customer（客户）

#### 13.2.1 Cost 成本定价

```
成本 = 变动成本 + 固定成本分摊
单价 = 成本 × (1 + 加成率)
示例：变动成本 30 元/件 + 固定成本分摊 10 元/件 = 40 元/件
加成率 50% → 单价 60 元
```

#### 13.2.2 Competitor 竞争定价

```
对照竞品价格区间，确定本项目价格定位：
竞品 A：100 元（高端）
竞品 B：60 元（中端）
竞品 C：30 元（低端）
本项目定位：50 元（中端偏下，性价比策略）
```

#### 13.2.3 Customer 客户定价

```
基于用户付费意愿调研：
50 份调研样本，68% 用户接受 9.9 元/月
- 35% 用户接受 5 元/月
- 68% 用户接受 9.9 元/月
- 22% 用户接受 19.9 元/月
最终定价：9.9 元/月（覆盖最大用户群）
```

## 十七、build.py 接口

### 17.1 命令行用法

```bash
python build.py --data data.json --out output.docx
python build.py --demo --out demo.docx
```

- `--data`：数据 JSON 文件路径（必填，与 --demo 二选一）
- `--out`：输出 docx 路径（必填，自动创建目录）
- `--demo`：使用内置示例数据生成演示文档

### 17.2 build.py 字段处理

build.py 处理 45 个顶层字段，缺字段时用合理默认值，不会报错。新字段（policy_citations/scientific_challenges/literature_review/algorithm_comparison/tech_roadmap/formulas/economic_benefits/project_innovation/industry_value/marketing_4p/pricing_3c/financial_statements/practice_process/tech_barriers）独立成节，在 11 大栏目后追加。

### 17.3 输出文件命名

默认输出到当前目录，建议命名 `{赛道}_{项目代号}_{申报日期}.docx`，如 `main_易舍_20250420.docx`。

### 17.4 字数档自动适配

build.py 根据 `data.competition_level` 字段自动选择字数档：
- `school` → 校赛版（精简）
- `province` → 省赛版（标准）
- `national` → 国赛版（深度）

未指定默认 `province`（省赛版）。字数档影响部分章节的展开/精简（如政策引用 5/8/10+ 篇，文献综述 10/20/30+ 篇）。

## 十八、质检清单

提交前逐项检查（30 项）：

### 18.1 基础格式（5 项）
1. 项目名称 ≤25 字，含产品代号，无"基于...的..."堆砌
2. 赛道已确认（main/red_journey/vocational），与组别匹配
3. 竞级已确认（school/province/national），与字数档匹配
4. docx 字体格式正确（宋体小四正文、黑体三号标题、1.5 倍行距、首行缩进 2 字符、A4 页面、页边距上下 2.54cm 左右 2.5cm）
5. 无空白页、无乱码、页码底部居中

### 18.2 核心栏目（10 项）
6. 执行摘要 500~800 字，六要素齐全（一句话+市场+产品+模式+团队+融资）
7. 一句话项目 ≤30 字，含目标用户 + 痛点 + 方式
8. 行业背景含数据来源（艾瑞/IDC/国家统计局/白皮书）+ 政策文件名
9. TAM/SAM/SOM 三级测算含表格 + 数据来源
10. 竞品分析 3~5 个直接竞品 + 2~3 个间接竞品，5 列对比表
11. 商业模式画布 9 要素齐全，每格 30~50 字
12. CAC/LTV 测算含 LTV/CAC 比值（≥3）
13. 运营现状含 KPI 表（北极星 + 次级指标）
14. 风险分析 4 类齐全，每类含概率+影响+应对
15. 团队 5~8 人，商科+技术+设计复合，含分工

### 18.3 11 项案例化必加章节（15 项）
16. 国家政策引用 ≥10 篇（校赛 5/省赛 8/国赛 10+），按时间倒序，含发文机关+文号+标题+时间+关键表述
17. 科学挑战 3 段结构（校赛 1~2/省赛 2~3/国赛 3），层层递进，含子挑战与文献支撑
18. 国内外研究现状综述 ≥30 篇文献（校赛 10/省赛 20/国赛 30+），英文 ≥60%，含 SCI 一区/二区
19. 算法对比表 ≥3 维度对比 + 选型结论 + 文献引用
20. 技术路线图 ≥3 张（校赛 1/省赛 2/国赛 3），含图号标题 + 节点关系表
21. 数学公式 ≥4 个（校赛 1/省赛 2~3/国赛 4+），含编号 + 变量定义 + 算法流程
22. 社会经济效益量化 ≥12 项指标（校赛 6/省赛 10/国赛 12），4 列对比，提升幅度双重表达
23. 个人成长 3 段结构（学习成长/实践经历/反思突破），第一人称，含"从 X 变 Y"
24. 项目创新 3 套（技术/模式/业态），每套含量化提升数据
25. 产业价值 4 维度（市场规模/就业带动/税收贡献/社会效益），各维度有量化数据
26. 团队协作 4 维度（分工/互补/共识/危机处理），含危机处理案例
27. 完整商业部分 4P + 3C + SWOT + 5 年三表齐全

29. NPV 含折现率假设与结论
30. 实践过程含 4 类活动 + ≥5 张图说明 + ≥3 家合作协议；技术壁垒含 ≥1 项专利 + 检测报告 + 系统验证

任一项不达标 → 返回修改。30 项全过 → 可提交。

### 18.4 字数自动检查

撰写完成后用脚本核对各栏目字数：
- 执行摘要 500~800（校赛）/500~800（省赛）/800~1000（国赛）
- 市场分析 1500~2000 / 2000~2500 / 2500~3500
- 产品介绍 1000~1500 / 1500~2000 / 2000~3000
- 商业模式 800~1200 / 1200~1500 / 1500~2000
- 运营现状 800~1200 / 1200~1500 / 1500~2000
- 融资计划 500~800 / 800~1000 / 1000~1200
- 风险分析 500 / 800 / 1000
- 个人成长 500~800 / 1000~1500 / 1500~2000

低于下限或高于上限均需调整。

### 18.5 错别字检查

提交前对照高频错别字自检：的地得混用 / 作为-做为 / 既-即 / 附-符 / 藉-借 / 在-再 / 象-像 / 的-得（"达到 95%"不是"达到 95% 的"）。

### 18.6 格式终检

打开 docx 文件，目测检查：
- 字体（正文宋体小四、标题黑体三号）
- 行距（1.5 倍）
- 首行缩进（2 字符）

## 十九、学校差异处理

不同学校互联网+校赛模板有微调，处理规则：

**赛道顺序差异**：个别学校把"个人成长"放团队介绍前，或合并"风险分析"与"运营现状"。按学校下发模板调整 build.py 的 build() 方法调用顺序。

**字体差异**：少数学校要求"仿宋 GB2312"正文或"楷体"标题。修改 build.py 的 FONT_SONG/FONT_HEI 常量。

**页边距差异**：部分学校要求 3cm 左右边距。修改 build.py setup_page() 中的 left_margin/right_margin。

**栏目增减**：
- 部分学校要求"路演答辩记录"栏 → 在 build() 中追加 _add_defense_record() 方法
- 部分学校要求"诚信承诺书"栏 → 增加独立签字栏
- 红色之旅赛道增加"红色帮扶成效"栏 → 已在 _add_operation_status() 中内嵌

**级别差异**：
- 国赛：11 大栏目全要 + 11 项案例化必加章节全要 + 5 年三表 + 4 维度评审对应章节
- 省赛：11 大栏目全要 + 11 项案例化必加章节（精简版）+ 5 年表 + 4 维度评审对应章节
- 校赛：可省部分案例化必加章节 + 1~2 年财务 + 4 维度评审精简版

适配流程：先问"学校下发的模板有特殊要求吗？"→ 若有则按学校模板调整 → 若无按国赛模板处理。适配完成后告知用户"已按 XX 学校模板调整，请核对栏目顺序与字体"。

### 19.1 自定义模板适配步骤

1. 询问"学校名称？是否下发模板？"
2. 若有模板，让用户提供 docx/pdf 模板或截图
3. 对照本 skill 标准模板，标记差异点（栏目顺序、字体、页边距、增减栏）
4. 修改 build.py 对应函数（顺序调整 / 常量修改 / 增删方法）
5. 重新生成 docx，告知用户"已按 XX 学校模板调整"

适配修改记录到 worklog.md，便于后续项目复用。自检不通过 → 重新调整 → 再生成 → 再自检。本 skill 执行流程：触发 → 赛道确认 → 竞级确认 → 信息采集 → 撰写 11 大栏目 + 11 项案例化章节 → 调 build.py 生成 docx → 30 项质检 → 提交。

## 二十、与挑战杯创业赛道对比速查表

互联网+与挑战杯创业赛道均属"创业计划书"类竞赛，但评审维度与侧重差异显著：

| 维度 | 互联网+ 2025 | 挑战杯创业赛道 |
|------|-------------|---------------|
| 主办 | 教育部 | 共青团中央 |
| 性质 | 创新创业大赛 | 课外学术科技作品竞赛（创业计划类） |
| 产出 | 商业计划书（BP） | 创业计划书 |
| 评审维度 | 个人成长 30% + 项目创新 30% + 产业价值 25% + 团队协作 15% | 创新性 35% + 商业性 30% + 团队 20% + 社会价值 15% |
| 个人成长权重 | 30%（重点） | 不单独计分 |
| 社会价值权重 | 0%（并入产业价值） | 15%（独立维度） |

| 字数 | 1.5 万~4 万字（3 档） | 1 万~1.5 万字 |

| 是否要求落地 | 不强制（创意期可参赛） | 不强制 |
| 国赛金奖率 | 约 1% | 约 2% |
| 案例化必加章节 | 11 项（政策/挑战/文献/算法/路线/公式/效益/4维度/4P3C+5年三表/实践+壁垒）| 6 项（政策/挑战/文献/算法/路线/效益）|

**关键区别**：
1. 互联网+ 2025 把"个人成长"提到 30% 首位，挑战杯仍以"创新性 + 商业性"为核心。
2. 互联网+ 2025 强调"项目创新 30%"必须有技术深度（科学挑战/文献/算法/公式），挑战杯更强调"创新性 35%"但允许纯模式创新。
3. 互联网+ 2025 要求完整 5 年财务三表 + 4P3C + SWOT，挑战杯财务要求相对宽松。
4. 互联网+ 2025 要求实践过程 + 技术壁垒章节，挑战杯不强制。

同一项目参加两赛，BP 需差异化：互联网+版本突出"我学到了什么/我改变了什么"第一人称成长叙事 + 技术深度 + 完整商业；挑战杯版本突出"项目创新性 + 社会价值"第三人称客观叙事。混用会导致评审维度不匹配，直接淘汰。

本 skill 仅处理互联网+版本。挑战杯创业赛道请走挑战杯 skill（按学术科技作品竞赛框架调整）。

**赛道选择决策**：
- 在籍本科生/研究生选高教主赛道
- 项目含老区/乡村帮扶主题选红色之旅
- 高职/中职生选职教赛道
- 同一项目可同时报高教主赛道与红色之旅（双报），但 BP 需差异化撰写

## 二十一、FAQ

### Q1：项目处于创意期，无任何运营数据，BP 怎么写？

A：诚实写"创意期"+"用户调研数据"。执行摘要突出"市场机会 + 团队 + MVP 设计"，运营现状写"MVP 原型 + 用户调研 50 份 + 3 家合作意向"，财务预测保守估算（Year1 营收不超过 SAM × 5%）。禁止编造"已注册公司、营收 100 万、A 轮融资 500 万"。创意期 BP 重点突出"个人成长 30%"和"项目创新 30%"两维度，弱化"产业价值 25%"。

### Q2：纯商业模式创新项目（无技术深度），科学挑战/文献综述/算法对比怎么处理？

A：纯商业模式创新项目可省略"数学公式"章节，但其他必加章节仍需：
- 国家政策引用 10+：引用创新创业、数字经济政策
- 科学挑战 3 段：可改为"业务挑战 3 段"（如用户增长挑战、商业化挑战、规模化挑战）
- 文献综述 30+：引用商业模式、用户增长、互联网产品相关文献
- 算法对比表：可改为"商业模式对比表"（如对比 3 种盈利模式）
- 技术路线图 3 张：可改为"业务路线图 3 张"（如用户增长路径、商业化路径、规模化路径）
- 社会效益 12 项：仍需量化对比

### Q3：3 档字数版本如何选择？

A：根据赛级与项目阶段：
- 校赛（创意期/种子期）→ 校赛版（1.5 万~2 万字）
- 省赛（MVP 期/早期运营期）→ 省赛版（2.5 万~3 万字）
- 国赛（早期运营期/成长期）→ 国赛版（3 万~4 万字）

晋级后必须升级字数档，校赛铜奖晋级省赛必须从校赛版升级省赛版，省赛银奖晋级国赛必须升级国赛版。

### Q4：5 年财务三表数据如何估算？

A：基于 3 个假设：
1. 用户增长假设：Year1 用户 = SOM × 5%，Year3 = SOM × 30%，Year5 = SOM × 60%
2. 营收假设：营收 = 用户数 × 客单价 × 复购次数
3. 成本假设：变动成本 = 营收 × (1 - 毛利率)，毛利率 30%~60%（互联网平均）

5 年三表必须满足：
- 利润表：营收 - 成本 - 费用 - 税 = 净利润
- 现金流量表：经营 + 投资 + 筹资 = 现金净增加
- 资产负债表：资产 = 负债 + 所有者权益（会计恒等式）

### Q5：4 维度评审对应章节如何撰写才能拿高分？

A：按权重排序：
- 个人成长（30%）：第一人称 + 3 段结构（学习成长/实践经历/反思突破）+ "从 X 变 Y" + 失败复盘
- 项目创新（30%）：3 套创新点（技术/模式/业态）+ 量化提升数据 + MVP 验证 + 专利支撑
- 产业价值（25%）：4 维度（市场/就业/税收/社会）+ 5 年财务 + 12 项社会效益量化
- 团队协作（15%）：4 维度（分工/互补/共识/危机）+ 复合背景表 + 危机案例

前两维占 60%，必须双 80+ 才有省赛银奖希望。

### Q6：技术型项目（如消防无人机）和商业模式型项目（如校园二手平台）的 BP 有何差异？

A：技术型项目重点突出：
- 科学挑战 3 段（数据→算法→系统）
- 文献综述 30+ 篇（含 SCI 一区/二区）
- 算法对比表 + 数学公式
- 技术壁垒章节（专利 + 检测报告 + 系统验证）
- 实践过程章节（团队学习 + 企业考察 + 实物制作 + 试飞验证）

商业模式型项目重点突出：
- 商业模式画布 9 要素
- 4P + 3C + SWOT
- 5 年财务三表
- 用户调研 + 竞品分析
- 个人成长叙事

两类项目都必须有 4 维度评审对应章节。

### Q7：互联网+ 2025 与 2024 评审维度差异如何处理？

A：2024 评审维度：创新性 + 商业性 + 团队 + 社会价值（4 维各 25%）。2025 评审维度：个人成长 30% + 项目创新 30% + 产业价值 25% + 团队协作 15%。

最显著变化：
1. "个人成长"30% 跃居首位（2024 不单独计分）→ BP 必须突出第一人称成长叙事
2. "社会价值"15% 并入"产业价值"25% → BP 必须把社会效益与产业价值合并表述
3. "团队"15% 改名"团队协作"15% → BP 必须强调协作机制（分工/互补/共识/危机）

旧版 BP（2024 框架）必须升级到 2025 框架，否则评审维度不匹配，直接淘汰。

### Q8：JSON 字段缺失会怎样？

A：build.py 对每个字段都有合理默认值，缺字段不会报错，会输出占位文本提示用户填写。但 P0 字段缺失会被 _validate_data() 标记为 warning，建议补全后再提交。

### Q9：如何快速生成 demo 文档？

A：`python build.py --demo --out demo.docx` 即可生成内置示例文档（消防无人机火场救援系统主题），用于查看格式与栏目结构。生成后可对照 demo 修改自己的 data.json。

### Q10：如何处理跨学科项目（如 AI + 医疗）？

A：跨学科项目的政策引用、文献综述、科学挑战需覆盖 2 个学科：
- 政策引用 10+：含 AI 政策 + 医疗政策
- 文献综述 30+：含 AI 顶会/顶刊 + 医疗顶刊
- 科学挑战 3 段：可按 AI 挑战 + 医疗挑战 + 跨学科挑战分层
- 算法对比 + 数学公式：以 AI 算法为主
- 社会效益 12 项：突出医疗价值 + AI 价值

跨学科项目是互联网+ 2025 "项目创新 30%"的高分点，建议充分利用。
