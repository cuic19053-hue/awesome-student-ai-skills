# 优秀毕业设计/论文申报书 Skill

本 skill 处理"优秀毕业设计/论文"申报全流程：信息采集 → 4 段结构撰写 → 摘要生成 → docx 生成 → 质检。优秀毕业设计/论文是大四（或研三/专科大三）学生毕业答辩后向学校/学院申报的"单课题学术成果"型荣誉，评审对象为**毕业设计/论文本身**（看 1 学期毕设成果），与"优秀毕业生"（看 4 年综合表现）属于完全不同的荣誉体系。

**输出形态**：A4 纸，黑体二号标题居中、宋体小四正文、1.5 倍行距、首行缩进 2 字符、"此致/敬礼！"格式、落款右对齐，含创新点表（3 列：类别/创新点描述/支撑材料）、研究阶段表（4 列：阶段/时间/工作内容/产出）、应用价值表（3 列：场景/价值描述/采纳证明）三张关键表。

## §0 适用场景与触发后第一步

用户进入对话后第一步必须确认两件事：①是申报"优秀毕业设计/论文"（本 skill 范围），还是申报"优秀毕业生"（走 outstanding_graduate skill）；②申报规格（校级 / 院级）。

### 0.1 触发条件

用户提到"优秀毕业设计""优秀毕业论文""毕设评优""毕业论文申报""优秀毕设""毕业设计评优""毕业论文评优""校级优秀毕业设计""院级优秀毕业设计""优秀本科毕业论文""优秀学位论文""毕设申报"等关键词，且本人已完成毕业答辩（大四下学期 / 研三 / 专科大三下）。

### 0.2 不适用（需走其他 skill）

- 优秀毕业生（4 年综合表现，2 000~2 500 字书信体）→ 走 outstanding_graduate skill
- 优秀学生 / 优秀团员 / 文明大学生（一学年跨度，1 500~2 000 字）→ 走评优其他 skill
- 国家奖学金（一学年跨度，1 200~2 000 字）→ 走 national_project_eval skill
- 挑战杯 / 互联网+（创业计划/学术作品赛，独立赛事）→ 走对应赛事 skill
- 大创 / 科研立项（独立项目，与大创局挂钩）→ 走对应 skill

### 0.3 触发后第一步

核对硬门槛与申报规格。若用户毕设未通过答辩，告知"优秀毕业设计/论文申报须以毕设通过答辩为前提，未通过答辩者不予申报"。区分校院规格与学制类型，分别按对应规范出具。

## §1 优秀毕业设计 vs 优秀毕业生 5 维度区分表

"优秀毕业设计/论文"与"优秀毕业生"是两个**完全独立**的荣誉体系，撰写方法、上报层级、推免加分均不同。撰写前必须确认用户申报的是哪一种，避免混淆。

| 维度 | 优秀毕业设计/论文 | 优秀毕业生 |
|------|---------------------|-----------|
| **评审对象** | 单个毕业课题（毕业设计/论文本身） | 4 年（研究生 3 年）综合表现 |
| **材料形式** | 申报书 2 000~3 000 字 + 摘要 300~500 字 + 成果附件 | 申请书 2 000~2 500 字（书信体） / 登记表 / 主要事迹 |
| **面向人群** | 大四毕设通过答辩者（含专科大三/研三） | 应届毕业生（4 年综合表现达标者） |
| **上报层级** | 校级（学院推荐 + 学校终审）/ 院级 | 省级 / 校级 / 基层就业专项 |
| **推免加分** | 校级优秀毕设一般加 0.5~1.0 学分（部分高校） | 校级优秀毕业生加 1~2 分（推免综合测评） |

### 1.1 5 维度硬区分要点

1. **评审对象不同**：优秀毕设看的是"1 个课题"的学术价值与创新性，不看 4 年综合表现；优秀毕业生看的是"4 年成长叙事"，不看单个课题
2. **材料形式不同**：优秀毕设是"申报书 + 摘要 + 成果附件"（论文/实物/代码），优秀毕业生是"申请书 / 登记表 / 主要事迹"
3. **面向人群不同**：优秀毕设面向"毕设通过答辩的应届生"，未通过答辩者不申报；优秀毕业生面向"4 年综合表现达标的应届生"
4. **上报层级不同**：优秀毕设只有"校级 + 院级"两档（无省级）；优秀毕业生有"省 / 校 / 基层"三档
5. **推免加分不同**：优秀毕设按"学分加分"（部分高校，加 0.5~1.0 学分）；优秀毕业生按"综合测评加分"（推免时加 1~2 分）

### 1.2 易混淆点速查

| 易混淆点 | 正确处理 |
|----------|----------|
| "我是优秀毕业生，要不要写优秀毕设申报书" | 不需要。两个荣誉独立申报，可同时参评，但材料分别撰写 |
| "优秀毕设和优秀毕业生哪个含金量更高" | 优秀毕业生含金量更高（4 年综合荣誉），但优秀毕设是"学术成果型"荣誉，对保研/科研岗加分更直接 |
| "优秀毕设有省级吗" | 没有。优秀毕设只有校级 + 院级两档（区别于优秀毕业生的省/校/基层三档） |
| "研究生能不能申报优秀毕设" | 可以。硕士/博士学位论文均可申报校级优秀学位论文，但须含外审盲评意见 |
| "毕设还没答辩能不能申报" | 不能。必须以毕设通过答辩为前提 |

### 1.3 与其他学术评优的关系

- **优秀毕业设计/论文**：本 skill 范围，毕设成果型荣誉
- **优秀学位论文（硕士/博士）**：研究生版本，本 skill 兼容（graduate_type=master/doctor）
- **挑战杯课外学术作品**：独立赛事，不是毕设评优，走 challenge_cup skill
- **大学生创新创业训练计划（大创）**：独立项目，可与大创项目挂钩但不是同一荣誉

## §2 硬门槛（两层，缺一不可）

### 2.1 绝对硬门槛（不达标直接劝退，4 项）

以下 4 项为各校官方文件明示的最低门槛，任一不达标直接劝退：

1. **毕业设计/论文已通过答辩**：毕设成绩合格及以上（不含不及格、不含延期答辩）
2. **答辩成绩排名前列**：通常要求毕设成绩位于专业前 20%（校级）/ 前 30%（院级），具体比例以学校文件为准
3. **无学术不端记录**：毕设查重率合格（本科 ≤30%、硕士 ≤10%、博士 ≤5%），无抄袭/违规作假/数据造假记录
4. **指导教师同意推荐**：导师须签署"同意推荐申报优秀毕业设计/论文"意见

**撰写阶段须在申报书开头或导师意见栏中明示上述 4 项达标情况**，便于评审专家 10 秒内完成硬门槛核查。

### 2.2 竞争性门槛（建议值，未达标不强制劝退但影响竞争力）

| 维度 | 院级建议值 | 校级建议值 |
|------|-----------|-----------|
| 毕设答辩成绩 | ≥80 分（良好） | ≥90 分（优秀） |
| 毕设查重率 | ≤25% | ≤15% |
| 标志性成果 | 实物/软件/论文 1 项 | 论文 1 篇 / 专利 1 项 / 实物 1 套 |
| 创新点数量 | 至少 1 项明确创新点 | 至少 2 项创新点（含 1 项方法创新或理论创新） |
| 应用价值 | 校内应用或导师课题组应用 | 校外单位采纳或产业转化 |
| 答辩组评价 | 答辩组 3 人以上评价为"优秀" | 答辩组全票"优秀"+ 推荐申报 |

竞争性门槛为建议值，部分学校配额宽松时可不达查重率门槛仍能获评院级；但申报校级时若不达建议值，须有其他强标志成果（如已发表 SCI 论文、已授权发明专利）补足。

### 2.3 触发硬门槛校验

撰写前主动核对：
- "毕设答辩通过了吗？成绩是多少？"
- "查重率多少？有没有学术不端记录？"
- "导师同意推荐你申报优秀毕设吗？"
- "申报校级还是院级？"

任一项不达标 → 告知硬门槛未达，建议改报其他荣誉；用户坚持申报则如实撰写，由用户承担后果（详见 §17 免责声明）。

## §3 5 类毕业设计对照表

不同毕业设计类型撰写方法不同，撰写前须先确认 thesis_type 字段。5 类毕业设计对照表如下：

| 类型 | 适用专业 | 核心特征 | 研究方法主线 | 创新点侧重 | 典型成果 |
|------|----------|----------|--------------|------------|----------|
| **实验研究** | 理工科（物理/化学/生物/材料/医学） | 通过实验验证假设/发现规律 | 文献调研 → 实验设计 → 数据采集 → 数据分析 → 结论 | 理论创新 / 方法创新 | 实验数据集、SCI 论文、专利 |
| **工程设计** | 工科（机械/土木/电气/化工/航空航天） | 完成具体工程设计方案 | 需求分析 → 方案设计 → 详细设计 → 仿真验证 → 优化迭代 | 方法创新 / 应用创新 | 设计图纸、仿真报告、实物样机 |
| **理论研究** | 理科（数学/物理/理论力学）/ 文科（哲学/历史/文学） | 推导/证明理论命题 | 文献综述 → 命题提出 → 推导/证明 → 验证 → 结论 | 理论创新 | 学术论文、定理证明、新模型 |
| **软件开发** | 计算机/软件工程/信息管理 | 完成软件系统设计与实现 | 需求分析 → 系统设计 → 编码实现 → 测试验证 → 部署运行 | 方法创新 / 应用创新 | 可运行软件、源代码、测试报告 |
| **艺术设计** | 艺术类（视觉传达/环境设计/服装设计/工业设计） | 完成艺术作品创作 | 主题确立 → 调研分析 → 创意构思 → 作品制作 → 展示答辩 | 应用创新 | 艺术作品、设计说明、展览方案 |

### 3.1 5 类毕业设计撰写要点

#### 3.1.1 实验研究类

撰写要点：
1. **课题选择段**：明确科学问题、研究意义、与学科前沿的对接
2. **研究方法段**：详细描述实验装置、材料、参数、数据采集方法、统计方法
3. **创新点段**：理论创新（发现新规律）/ 方法创新（改进实验方法）/ 应用创新（应用于新场景）
4. **成果与应用段**：实验数据集、SCI 论文、专利、后续研究方向

#### 3.1.2 工程设计类

撰写要点：
1. **课题选择段**：明确工程背景、设计目标、技术指标
2. **研究方法段**：CAD 建模 / 仿真分析 / 优化算法 / 验证方法
3. **创新点段**：方法创新（改进设计方法）/ 应用创新（应用于新场景）
4. **成果与应用段**：设计图纸、仿真报告、实物样机、产业化前景

#### 3.1.3 理论研究类

撰写要点：
1. **课题选择段**：明确理论问题、学术价值、与现有理论的对比
2. **研究方法段**：文献综述方法、推导/证明思路、验证方法
3. **创新点段**：理论创新（提出新理论/改进现有理论）
4. **成果与应用段**：学术论文、定理证明、新模型、后续研究方向

#### 3.1.4 软件开发类

撰写要点：
1. **课题选择段**：明确软件需求、用户痛点、市场背景
2. **研究方法段**：需求分析方法、系统架构、开发框架、测试方法
3. **创新点段**：方法创新（改进算法）/ 应用创新（应用于新场景）
4. **成果与应用段**：可运行软件、源代码、测试报告、用户反馈

#### 3.1.5 艺术设计类

撰写要点：
1. **课题选择段**：明确创作主题、艺术价值、文化背景
2. **研究方法段**：调研方法、创意构思方法、制作工艺、展示方式
3. **创新点段**：应用创新（艺术语言/媒介/表现形式创新）
4. **成果与应用段**：艺术作品、设计说明、展览方案、社会反响

## §4 4 段结构详解

优秀毕业设计/论文申报书采用 **4 段结构**，配比按字数版本动态调整：

```
标题：优秀毕业设计/论文申报书（黑体二号居中）

称呼：尊敬的评审委员会：（顶格，全角冒号）

开头段（150~200 字，1 段）：
  身份 + 申报规格 + 毕设题目 + 答辩成绩 + 导师 + 进入正文

一、课题选择与意义（400~600 字，重点段之一）
  课题来源 + 科学/工程问题 + 学术/应用意义 + 与学科前沿对接 + 研究目标

二、研究方法与技术路线（500~700 字，重点段之一）
  研究方法主线（按 thesis_type 分流）+ 技术路线图说明 + 关键技术 + 数据/材料/装置

三、创新点（400~600 字，重点段之二）
  按 3 类创新（理论/方法/应用）分别阐述 + 创新点表（3 列：类别/创新点描述/支撑材料）

四、成果与应用价值（300~500 字，重点段之三）
  成果清单（论文/专利/实物/软件）+ 应用场景 + 采纳证明 + 后续研究方向

结尾段（80~150 字）：
  毕设总结 + 致谢导师 + 朴素表态 + "此致/敬礼！"

落款（右对齐）：
  申请人：XXX
  指导教师：XXX 教授
  XXXX 年 XX 月 XX 日

摘要（300~500 字，独立页或申报书末尾）：
  课题背景一句话 + 研究方法一句话 + 主要创新点 1-3 条 + 主要成果与应用价值一句话
```

### 4.1 标题

格式：黑体二号，居中，段前段后 12pt。

文本：根据申报规格动态填充——校级填"校级优秀毕业设计申报书"（10 字）/ 校级优秀毕业论文申报书 / 院级填"院级优秀毕业设计申报书" / 院级优秀毕业论文申报书。**不要写"2025 届校级优秀毕业设计申报书"**（年份冗余），标题简洁有力，与学校下发模板保持一致。

**thesis_type 字段对应标题写法**：
- 实验研究/工程设计/软件开发/艺术设计 → "优秀毕业**设计**申报书"
- 理论研究 → "优秀毕业**论文**申报书"
- 硕士/博士学位论文 → "优秀学位论文申报书"

### 4.2 称呼

默认"尊敬的评审委员会："（理工类院校常见，5 种称呼速查见 §5）。冒号用全角"："。

### 4.3 开头段（150~200 字，1 段）

句式 3 句结构：
1. 身份 + 申报规格："我是 XX 学院 XX 专业 2021 级学生 XXX，毕业设计题目《XXX》，指导教师为 XX 教授，特此申报 2025 届校级/院级优秀毕业设计/论文。"
2. 毕设关键数据："毕设答辩成绩 XX 分（优秀），专业排名 X/N，查重率 X.X%；[标志成果 1]；[标志成果 2]。"
3. 进入正文："现将毕业设计情况汇报如下："

**禁止**：抒情开头（时光荏苒/岁月如梭/四年光阴转瞬即逝/感慨万千）、感谢导师培养、回顾毕设过程、套用"白驹过隙"等成语。

### 4.4 一、课题选择与意义（400~600 字）

撰写要点 4 项：

**(1) 课题来源**：
- 导师科研项目子课题（须含项目编号）
- 自选题（须说明选题动机）
- 校企合作项目（须含企业名称）
- 竞赛延伸课题（须含竞赛名称）

**(2) 科学/工程问题**：明确课题要解决的核心问题（1 个主问题 + 2-3 个子问题），不能用"研究 XX 的应用"模糊表述。

**(3) 学术/应用意义**：
- 学术意义：填补 XX 研究空白 / 改进 XX 理论 / 提出 XX 新方法
- 应用意义：解决 XX 工程问题 / 服务 XX 产业 / 惠及 XX 群体

**(4) 与学科前沿对接**：明确课题与近 3 年学科前沿（如 AI for Science、双碳目标、芯片自主可控、健康中国 2030 等）的对接点。

**(5) 研究目标**：3-5 个具体研究目标，每个目标对应 1-2 个研究内容。

正面示例（约 200 字）：
> 本课题来源于国家自然科学基金项目"基于深度学习的医学影像分割方法研究"（项目编号 62XXXXXXXX），针对现有医学影像分割方法在小样本场景下精度不足的问题，研究基于对比学习的小样本医学影像分割方法。学术意义在于改进现有对比学习框架在医学影像领域的迁移性能，应用意义在于为基层医院提供低成本 AI 辅助诊断方案，与"健康中国 2030"战略对接。研究目标包括：①构建小样本医学影像数据集；②设计对比学习分割网络；③在公开数据集上验证方法有效性。

反面示例：
> 我的毕业设计课题是关于深度学习在医学影像方面的应用研究，具有重要的理论意义和实践意义。（无项目编号、无科学问题、无研究目标）

### 4.5 二、研究方法与技术路线（500~700 字）

撰写要点 5 项，按 thesis_type 分流：

**(1) 研究方法主线**（5 类对照表见 §3）：
- 实验研究：文献调研 → 实验设计 → 数据采集 → 数据分析 → 结论
- 工程设计：需求分析 → 方案设计 → 详细设计 → 仿真验证 → 优化迭代
- 理论研究：文献综述 → 命题提出 → 推导/证明 → 验证 → 结论
- 软件开发：需求分析 → 系统设计 → 编码实现 → 测试验证 → 部署运行
- 艺术设计：主题确立 → 调研分析 → 创意构思 → 作品制作 → 展示答辩

**(2) 技术路线图说明**：用文字描述技术路线图各环节（如有技术路线图附件，须注明"详见附件 X"）。

**(3) 关键技术**：3-5 项关键技术，每项含技术名称 + 应用环节 + 解决的问题。

**(4) 数据/材料/装置**：
- 实验研究：数据集（含规模/来源/标注）、实验装置、材料参数
- 工程设计：设计参数、仿真软件、验证装置
- 软件开发：开发框架、数据库、测试用例
- 理论研究：推导前提、证明工具、验证模型
- 艺术设计：创作材料、工艺流程、展示方式

**(5) 研究阶段表**：4 列表格（阶段/时间/工作内容/产出），4-6 行，体现研究过程完整性。

正面示例（约 200 字）：
> 研究方法采用"文献调研 + 实验设计 + 数据采集 + 模型训练 + 性能评估"五阶段路线。关键技术包括：①对比学习预训练（解决小样本场景特征学习问题）；②Transformer 分割网络（解决医学影像全局依赖建模问题）；③迁移学习策略（解决跨设备数据分布差异问题）。实验数据使用公开数据集 ISIC 2018（2 595 张皮肤镜图像）+ 自建数据集（300 张基层医院皮肤镜图像，已脱敏）。研究阶段详见下表：
> [研究阶段表]

### 4.6 三、创新点（400~600 字）

撰写要点 3 项，按 §5 创新点 3 类分别阐述：

**(1) 创新点分类**：每条创新点必须明确归类为理论创新 / 方法创新 / 应用创新之一。

**(2) 创新点描述**：每条创新点 80-120 字，含"创新点名称 + 与现有方法对比 + 创新性体现 + 支撑材料"。

**(3) 创新点表**：3 列表格（类别/创新点描述/支撑材料），3-5 行。

正面示例（约 200 字）：
> 本课题创新点 3 项：
> ①**理论创新**：提出基于对比学习的小样本医学影像分割理论框架，首次将对比学习引入皮肤镜图像分割任务，与现有监督学习方法（如 U-Net、DeepLab v3+）相比，在小样本（≤100 张）场景下 Dice 系数提升 8.5%。支撑材料：SCI 二区论文 1 篇（已发表）。

> ③**应用创新**：将所提方法部署于基层医院皮肤镜设备，实现 0.3 秒/张实时分割，已与 XX 县人民医院合作验证。支撑材料：合作验证报告 1 份。

### 4.7 四、成果与应用价值（300~500 字）

撰写要点 4 项：

**(1) 成果清单**：按"论文 / 专利 / 软件著作权 / 实物 / 数据集 / 开源代码"6 类分类列出，每类须含数量 + 级别 + 作者排序。

**(2) 应用场景**：3-5 个具体应用场景，每个场景含"应用领域 + 应用方式 + 应用效果"。

**(3) 采纳证明**：校外单位采纳须附采纳证明；校内应用须附课题组/学院证明。

**(4) 后续研究方向**：2-3 个后续研究方向，每个方向含"研究问题 + 预期突破 + 应用前景"。

**(5) 应用价值表**：3 列表格（场景/价值描述/采纳证明），3-5 行。

正面示例（约 200 字）：
> 成果清单：SCI 二区论文 1 篇（第一作者，IF 5.2）、发明专利 1 项（第一发明人，实质审查中）、软件著作权 1 项、开源代码 1 套（GitHub 200+ stars）。应用场景：①基层医院皮肤镜辅助诊断（已与 XX 县人民医院合作验证，诊断准确率提升 12%）；②在线医疗平台 AI 辅助诊断接口（已接入 XX 互联网医院）；③医学院教学辅助（已用于 XX 医学院皮肤科教学）。后续研究方向：①多模态融合诊断（CT + 皮肤镜）；②联邦学习框架下的隐私保护分割。

### 4.8 结尾段（80~150 字）

撰写要点 3 项：
1. 毕设总结：1 句话总结毕设核心成果

3. 朴素表态：1 句话表态（不用"恳请领导批准"）

摘要为独立段落，置于申报书末尾或独立页，4 句结构：
1. **课题背景一句话**（30-50 字）：本课题研究 XX 问题，针对 XX 不足。
2. **研究方法一句话**（50-80 字）：采用 XX 方法，基于 XX 理论/框架，通过 XX 步骤开展研究。

> 本课题研究基于对比学习的小样本医学影像分割方法，针对现有监督学习方法在小样本场景下精度不足的问题。采用文献调研、实验设计、数据采集、模型训练、性能评估五阶段研究方法，基于对比学习理论框架，通过构建小样本数据集、设计多尺度特征融合模块、迁移学习策略开展研究。主要创新点：①理论创新——提出基于对比学习的小样本医学影像分割理论框架，首次将对比学习引入皮肤镜图像分割任务；②方法创新——设计多尺度特征融合模块（MSFF），通过跨尺度注意力机制实现病灶边界精修；③应用创新——将所提方法部署于基层医院皮肤镜设备，实现 0.3 秒/张实时分割。研究成果包括 SCI 二区论文 1 篇、发明专利 1 项、软件著作权 1 项、开源代码 1 套，已应用于基层医院辅助诊断、在线医疗平台 AI 接口、医学院教学辅助 3 个场景，具有显著的社会价值与产业前景。

## §5 创新点 3 类

优秀毕业设计/论文申报书的核心是**创新点**。创新点须按 3 类分别阐述，每类有明确判定标准与撰写规范。

### 5.1 创新点 3 类对照表

| 类别 | 定义 | 判定标准 | 典型表述 | 支撑材料 |
|------|------|----------|----------|----------|
| **理论创新** | 提出新理论 / 改进现有理论 / 发现新规律 | 与现有理论有明确对比，有理论推导或实验验证 | "首次提出 XX 理论框架""改进 XX 模型，与现有方法相比提升 XX%" | 学术论文、定理证明、理论推导 |
| **方法创新** | 提出新方法 / 改进现有方法 / 设计新算法 | 与现有方法有明确对比，有实验或仿真验证 | "设计 XX 模块/算法，相比基线方法提升 XX%""提出 XX 流程，缩短 XX 时间" | 发明专利、软件著作权、对比实验 |
| **应用创新** | 应用于新场景 / 服务新群体 / 解决新问题 | 有明确应用场景与采纳证明 | "将 XX 方法应用于 XX 场景，已与 XX 单位合作验证""服务 XX 群体，惠及 XX 人数" | 采纳证明、合作报告、用户反馈 |

### 5.2 创新点判定原则

**(1) "首次"原则**：理论创新与方法创新使用"首次提出""首次将 XX 引入 XX"时，须有文献综述支撑（已检索 XX 数据库，截至 XX 时间无同类研究）。

**(2) "对比"原则**：每条创新点须与现有方法/理论/应用对比，给出量化指标（如"提升 XX%""缩短 XX 时间""降低 XX 成本"）。

**(3) "支撑"原则**：每条创新点须有支撑材料（论文/专利/软著/采纳证明），无支撑材料的创新点不予采纳。

### 5.3 创新点 3 类撰写规范

#### 5.3.1 理论创新撰写规范

句式：**首次提出 / 改进 [理论名称]，与现有 [对比理论] 相比 [量化优势]，支撑材料：[论文/定理/推导]。**

正面示例：
> 首次提出基于对比学习的小样本医学影像分割理论框架，与现有监督学习方法（U-Net、DeepLab v3+）相比，在小样本（≤100 张）场景下 Dice 系数提升 8.5%。支撑材料：SCI 二区论文 1 篇（已发表）。

反面示例：
> 提出了新的理论，具有重要创新意义。（无理论名称、无对比、无量化、无支撑）

#### 5.3.2 方法创新撰写规范

句式：**设计 / 提出 [方法/模块/算法名称]，通过 [技术细节] 解决 [问题]，与基线方法相比 [量化优势]，支撑材料：[专利/软著/实验]。**

正面示例：
> 设计多尺度特征融合模块（MSFF），通过跨尺度注意力机制实现病灶边界精修，与基线 U-Net 相比边界 IoU 提升 5.2%。支撑材料：发明专利 1 项（实质审查中）。

反面示例：
> 设计了新的算法，效果很好。（无方法名称、无技术细节、无量化、无支撑）

#### 5.3.3 应用创新撰写规范

句式：**将 [方法/技术] 应用于 [新场景]，与现有应用相比 [新价值]，已 [合作/采纳情况]，支撑材料：[采纳证明/合作报告]。**

正面示例：
> 将所提方法部署于基层医院皮肤镜设备，实现 0.3 秒/张实时分割，已与 XX 县人民医院合作验证（诊断准确率提升 12%）。支撑材料：合作验证报告 1 份。

反面示例：
> 本课题有重要的应用价值。（无场景、无新价值、无合作情况、无支撑）

### 5.4 创新点常见错误

- **创新点过多**：3-5 条为宜，超过 5 条评审专家会质疑"是否每条都站得住脚"
- **创新点过少**：少于 2 条则竞争力不足（申报校级至少 2 条）
- **创新点混淆**：理论创新/方法创新/应用创新必须分类清楚，不能"既算理论创新也算方法创新"
- **创新点无支撑**：每条创新点必须有论文/专利/软著/采纳证明支撑
- **创新点无量化**：每条创新点必须有量化指标（提升 %、缩短时间、降低成本等）

## §6 3 档字数版本

不同申报规格与不同学校的字数要求严格区分，撰写前须先确认目标档位：

| 档位 | 适用规格 | 字数区间 | 摘要字数 | 上限 | 备注 |
|------|----------|----------|----------|------|------|
| 短档 | 院级（学院组织评审） | 2 000~2 500 字 | 300 字 | 2 800 字 | 学院初审规格，含 1-2 项创新点 |
| 中档 | 校级（学院推荐 + 学校终审） | 2 500~3 000 字 | 400 字 | 3 200 字 | 学校终审规格，含 2-3 项创新点 |
| 长档 | 校级（评审较严学校） | 3 000~3 500 字 | 500 字 | 3 800 字 | 顶尖高校/硕士学位论文用，含 3-5 项创新点 |

### 6.1 字数自检规则

撰写完成后须用脚本统计字数（不含标点、不含表格内文字、不含摘要），偏离区间超过 10% 须返工。

### 6.2 字数分配建议（中档校级 2 700 字基准）

- 开头：180 字（7%）
- 一、课题选择与意义：550 字（20%）
- 二、研究方法与技术路线：800 字（30%）
- 三、创新点：650 字（24%）
- 四、成果与应用价值：400 字（15%）
- 结尾：120 字（4%）

短档（院级 2 200 字基准）按比例缩减：开头 150 / 课题选择 450 / 研究方法 650 / 创新点 530 / 成果应用 320 / 结尾 100。

长档（校级 3 200 字基准）按比例扩展：开头 220 / 课题选择 650 / 研究方法 950 / 创新点 770 / 成果应用 470 / 结尾 140。

### 6.3 字数选择决策树

1. 用户提到"院级"或"学院评审" → 短档（2 000~2 500 字）
2. 用户提到"校级"或"学校终审" → 中档（2 500~3 000 字）
3. 用户提到"硕士学位论文"或"博士学位论文"或"顶尖高校" → 长档（3 000~3 500 字）
4. 用户无明确信息 → 默认中档（校级标准），生成后提示"如学校有特殊字数要求，可告知后调整"

**P1 重要**（缺则影响质量）：project_source、research_problem、research_method、key_technologies、research_stages、achievements、application_scenarios
**P2 可选**（缺则用占位）：student_id、phone、plagiarism_rate、adoption_proofs、future_research

追问话术示例：
- 用户说"我毕设做得不错" → "毕设题目全称？指导教师姓名 + 职称？答辩成绩？查重率？"
- 用户说"我有几个创新点" → "每个创新点是什么？属于理论创新、方法创新还是应用创新？有什么支撑材料？与现有方法对比有什么优势？"
- 用户说"我发了论文" → "题目？期刊？级别（SCI/EI/核心）？你是第几作者？"
- 用户说"我有专利" → "专利名称？专利类型（发明/实用新型/外观）？状态（已授权/实质审查中）？你是第几发明人？"
- 用户说"我的研究有应用价值" → "应用在什么场景？合作单位？采纳证明？效果数据？"

**复述确认**：所有信息采完后，按"毕设信息 / 课题信息 / 研究方法 / 创新点 / 成果应用"顺序复述给用户确认，再进入撰写阶段。

## §10 雷区 10 条

撰写阶段须避开以下 10 条雷区，任一命中即可能被评审降级或不通过：

### 10.1 雷区 1：编造创新点

**禁止**：编造未实际取得的创新点。每条创新点必须有真实支撑材料（论文/专利/软著/采纳证明）。

**正面写法**：用户未提供真实创新点时用占位符 `___` 标注，提醒用户补全。

### 10.2 雷区 2：创新点无量化对比

**禁止**："本课题创新点具有显著优势""效果优于现有方法"等无量化表述。

**正面写法**：每条创新点须有"与现有 XX 方法相比，提升 X.X%"等量化对比。

### 10.3 雷区 3：研究方法与课题类型不匹配

**禁止**：实验研究类毕设写"理论推导"，工程设计类毕设写"实验验证"，软件开发类毕设写"理论分析"。

**正面写法**：按 thesis_type 5 类对照表（§3）选择匹配的研究方法主线。

### 10.4 雷区 4：抒情开头

**禁止**：时光荏苒/岁月如梭/一年毕设时光转瞬即逝/感慨万千等成语开头。

**正面写法**：直述身份 + 申报意图 + 毕设题目 + 答辩成绩 + 导师。

### 10.5 雷区 5：形容词代替事实

**禁止**："研究深入""方法新颖""成果丰硕""应用广泛"等无数据支撑词。

**正面写法**：量化表达（创新点数量、提升百分比、采纳单位数、合作时长）。

### 10.6 雷区 6：成果不写级别与作者排序

**禁止**："发表 SCI 论文""申请发明专利"无级别无排序。

**正面写法**："以第一作者在《Knowledge-Based Systems》（SCI 二区，IF 5.2）发表论文 1 篇""作为第一发明人申请发明专利 1 项（实质审查中，受理号 CN2024XXXXXXXX）"。

### 10.7 雷区 7：应用价值无采纳证明

**禁止**："本课题有重要的应用价值""具有广阔的产业化前景"无具体场景无采纳证明。

**正面写法**：3-5 个具体应用场景 + 每个场景的采纳证明 + 量化效果（如"诊断准确率提升 12%"）。

### 10.8 雷区 8：致谢段过度抒情

**禁止**："感谢导师一年来的悉心教导，谆谆教诲，让我如沐春风……"等抒情致谢。

**正面写法**："感谢导师 XX 教授一年来的悉心指导"一句话带过，重点在毕设成果本身。

### 10.9 雷区 9：摘要与正文脱节

**禁止**：摘要写"提出 3 项创新点"，正文只详述 2 项；摘要写"已应用于 3 个场景"，正文只列 2 个。

**正面写法**：摘要与正文创新点、成果、应用场景数量一致，措辞对应。

### 10.10 雷区 10：忽视研究阶段表

**禁止**：研究方法段只写文字描述，无研究阶段表。

**正面写法**：必含 4-6 行研究阶段表（4 列：阶段/时间/工作内容/产出），体现研究过程完整性。

## §11 评审专家视角反推写作法

### 11.1 评审专家工作模式

- **评审专家人数**：3-5 人/项目（典型配置）
- **每份材料阅读时长**：5-8 分钟（含摘要）
- **评议流程**：硬门槛扫描 → 创新点识别 → 研究方法评估 → 成果价值确认 → 综合打分

### 11.2 评审专家 4 步扫描法

| 步骤 | 时长 | 关注点 | 撰写对应 |
|------|------|--------|----------|
| ① 硬门槛扫描 | 15 秒 | 答辩成绩/查重率/导师推荐 | 开头段第 2 句直接列毕设关键数据 |
| ② 创新点识别 | 60 秒 | 创新点数量/类别/量化/支撑 | 第三段创新点表 3 列直接呈现 |
| ③ 研究方法评估 | 90 秒 | 研究方法匹配性/技术路线/数据 | 第二段研究阶段表 + 关键技术列表 |
| ④ 成果价值确认 | 30 秒 | 论文/专利/采纳证明/应用场景 | 第四段成果清单 + 应用价值表 |

### 11.3 撰写顺序铺排策略

按"硬门槛 → 创新点 → 研究方法 → 成果价值"顺序在开头段集中铺排，让评审专家 1 分钟内完成 4 步扫描：

**开头段示范**（180 字）：
> 我是计算机科学与技术学院计算机科学与技术专业 2021 级学生张明，毕业设计题目《基于对比学习的小样本医学影像分割方法研究》，指导教师为张伟教授，特此申报 2025 届校级优秀毕业设计。毕设答辩成绩 92 分（优秀），专业排名 1/87，查重率 8.5%；以第一作者发表 SCI 二区论文 1 篇（IF 5.2），作为第一发明人申请发明专利 1 项（实质审查中）；3 项创新点（理论 + 方法 + 应用），已与 XX 县人民医院合作验证。现将毕业设计情况汇报如下：

### 11.4 评审专家反感点

- 开头抒情（占 60% 网络范文，专家反感）
- 形容词代替事实（占 80%，专家反感）
- 创新点无量化对比（占 70%，专家反感）
- 研究方法与课题类型不匹配（占 30%，专家反感）
- 成果不写级别与作者排序（占 50%，专家反感）
- 应用价值无采纳证明（占 60%，专家反感）

### 12.1 详细正反例

#### 雷区 1：时光荏苒开头

✅ 正面：用事实陈述毕设成果（"3 项创新点 + SCI 二区论文 1 篇 + 发明专利 1 项"）

✅ 正面：以上是我毕业设计的情况汇报。感谢导师 XX 教授一年来的悉心指导。无论评选结果如何，我都将以优秀毕业设计的标准严格要求自己，在研究生阶段继续深入研究。

❌ 反面：本课题研究深入，方法新颖，成果丰硕，应用广泛。

✅ 正面：本课题 3 项创新点（理论 + 方法 + 应用），SCI 二区论文 1 篇（IF 5.2），发明专利 1 项，已应用于 3 个场景（基层医院 / 在线医疗 / 医学院教学）。

#### 雷区 5：创新点无量化

❌ 反面：本课题创新点具有显著优势，效果优于现有方法。

✅ 正面：理论创新——首次将对比学习引入皮肤镜图像分割，与 U-Net 相比 Dice 系数提升 8.5%；方法创新——设计 MSFF 模块，边界 IoU 提升 5.2%。

#### 雷区 6：研究方法与课题类型不匹配

❌ 反面：实验研究类毕设写"通过理论推导证明 XX 定理"

✅ 正面：实验研究类毕设写"通过实验设计 + 数据采集 + 模型训练 + 性能评估"五阶段路线

#### 雷区 7：成果不写级别

❌ 反面：发表 SCI 论文，申请发明专利。

✅ 正面：以第一作者在《Knowledge-Based Systems》（SCI 二区，IF 5.2）发表论文 1 篇，2025.03 见刊；作为第一发明人申请发明专利《一种基于对比学习的法律问答方法》（实质审查中，受理号 CN2024XXXXXXXX）。

#### 雷区 8：应用价值无采纳证明

❌ 反面：本课题具有广阔的产业化前景，应用价值重大。

✅ 正面：本课题已应用于 3 个场景：①基层医院辅助诊断（已与 XX 县人民医院合作验证，诊断准确率提升 12%）；②在线医疗 AI 接口（已接入 XX 互联网医院）；③医学院教学辅助（已用于 XX 医学院皮肤科教学）。

### 12.2 其他高频雷区

- 创新点过多（超过 5 条）→ 评审专家会质疑"是否每条都站得住脚"
- 创新点过少（少于 2 条）→ 竞争力不足（申报校级至少 2 条）
- 创新点混淆（既算理论创新也算方法创新）→ 必须分类清楚
- 论文不写期刊级别与作者排序 → 必含 SCI/EI/中文核心 + 第一/第二/通讯作者
- 专利不写状态 → 必含"已授权"/"实质审查中"/"已公开"
- 研究阶段表行数过少（少于 4 行）→ 须含 4-6 行
- 摘要字数不达标（少于 300 字）→ 须在 300-500 字区间
- 致谢段超过 50 字 → 一句话带过

## §15 build.py 接口说明

### 15.1 调用方式

```bash
# 方式 1：使用 JSON 数据文件
python build.py --data data.json --out output.docx

# 方式 2：使用内置示例数据（演示用）
python build.py --demo --out /tmp/test_outstanding_thesis.docx

# 方式 3：覆盖字数版本与申报规格
python build.py --demo --word-count-version brief --out demo_brief.docx
python build.py --demo --apply-level college --out demo_college.docx

# 方式 4：查看帮助
python build.py --help
```

### 15.2 命令行参数

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| --data | str | None | 数据 JSON 文件路径（与 --demo 二选一） |
| --out | str | 必填 | 输出 docx 文件路径 |
| --demo | flag | False | 使用内置示例数据生成演示文档 |
| --word-count-version | choice | None | 覆盖字数版本（brief 短档 / standard 中档 / enhanced 长档） |
| --apply-level | choice | None | 覆盖申报规格（school 校级 / college 院级） |

### 15.3 生成流程

1. 解析 JSON（或加载 DEFAULT_DATA）
2. 字段路由解析（material_form / apply_level / word_count_version / thesis_type / graduate_type）
3. 数据校验（输出 warnings，含硬门槛 4 项校验）
4. 构建 docx（标题 → 称呼 → 开头 → 课题选择 → 研究方法 → 创新点 → 成果应用 → 结尾 → 落款 → 摘要）
5. 保存到指定路径

### 15.4 输出文件规范

- A4 纸张，上下 2.54cm 左右 2.5cm 页边距
- 黑体二号标题居中（按 thesis_type 动态生成）
- 宋体小四正文，1.5 倍行距，首行缩进 2 字符
- 中英文同步设置（eastAsia / ascii / hAnsi）
- 研究阶段表 4 列（阶段/时间/工作内容/产出）
- 创新点表 3 列（类别/创新点描述/支撑材料）
- 应用价值表 3 列（场景/价值描述/采纳证明）
- "此致"另起一行空两格，"敬礼！"另起一行顶格
- 落款右对齐（申请人 + 指导教师 + 日期，3 行）
- 页脚居中页码

### 15.5 输出文件命名建议

- 校级：`校级优秀毕业设计申报书_张明_2025.docx`
- 院级：`院级优秀毕业设计申报书_张明_2025.docx`
- 论文类：`校级优秀毕业论文申报书_张明_2025.docx`
- 硕士/博士：`优秀学位论文申报书_张明_2025.docx`

文件名包含规格、姓名、毕业年份，便于学院归档。

### 15.6 缺失字段处理

- P0 必采字段缺失：触发 warning，仍生成 docx，但对应段落用占位符 `___` 标注
- P1 重要字段缺失：触发 warning，对应段落省略或简化
- P2 可选字段缺失：不触发 warning，直接省略

## §17 红线规则与免责声明

### 17.1 红线规则（撰写阶段禁止行为）

1. **禁止编造数据**：毕设题目、答辩成绩、查重率、创新点、论文、专利、采纳证明任一项不可编造。用户未提供真实数据时用占位符 `___` 标注
2. **禁止抒情开头**：不用"时光荏苒""岁月如梭""一年毕设时光转瞬即逝""感慨万千""白驹过隙"等成语
3. **禁止形容词代替事实**：不用"研究深入""方法新颖""成果丰硕""应用广泛"等无数据支撑词
4. **禁止"恳请领导批准"**：结尾用"无论评选结果如何，我都将以优秀毕业设计的标准严格要求自己"代替
5. **禁止创新点无量化对比**：每条创新点须有"与 XX 方法相比提升 X.X%"等量化对比
6. **禁止创新点无支撑材料**：每条创新点须有论文/专利/软著/采纳证明支撑
7. **禁止研究方法与课题类型不匹配**：按 thesis_type 5 类对照表（§3）选择匹配的研究方法主线
8. **禁止成果不写级别与作者排序**：每个成果须含级别 + 作者排序 + 时间
9. **禁止应用价值无采纳证明**：每个应用场景须含合作单位 + 采纳证明 + 量化效果
10. **禁止摘要与正文脱节**：摘要创新点数量、成果数量、应用场景数量须与正文一致

### 17.2 撰写阶段必检项

撰写完成后逐项核对：
- [ ] 硬门槛 4 项达标情况明示（答辩通过 + 成绩排名 + 查重合格 + 导师推荐）
- [ ] 课题来源含项目编号（如为导师项目子课题）
- [ ] 科学/工程问题明确（不能"研究 XX 的应用"模糊表述）
- [ ] 研究方法主线与 thesis_type 匹配
- [ ] 研究阶段表 4-6 行 4 列
- [ ] 创新点 3-5 条，按 3 类分类
- [ ] 每条创新点含量化对比 + 支撑材料
- [ ] 成果清单按 6 类（论文/专利/软著/实物/数据集/代码）分类
- [ ] 应用场景 3-5 个 + 采纳证明
- [ ] 摘要 300-500 字 4 句结构
- [ ] 字数符合规格（短/中/长档）
- [ ] 落款右对齐含申请人 + 指导教师 + 日期（3 行）
