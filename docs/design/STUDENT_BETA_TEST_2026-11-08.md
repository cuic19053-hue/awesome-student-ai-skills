# 学生申报工作台内测记录

测试日期：2026-11-08。结论：**未通过面向学生的完整流程验收**。

## 修复后复测

材料交付阻断补测：模型中断前已经输出闭合写作块，或在未闭合块内已出现下一同级章节边界时，可恢复可识别的前段供学生核对；未到达可识别边界的尾段不会作为完整章节导入。隔离浏览器使用受控本地模型模拟中途断流，确认页面提示整份材料未完成、请求只发一次；学生编辑、保存后下载的 Word 含修改后的正文。没有可恢复内容、服务进程被强制终止或存储不可用时，仍不能保证找回生成内容。

普通 Markdown 回复也可在结构明确时整理带子标题和完整表格的章节；示例与不完整内容按保守规则处理。导出时，学生可核对对话草稿与已保存正文的冲突；学校模板损坏或明确丢失时会提示并采用通用 Word 排版，损坏图片保留提示占位。模拟云端测试仅下载本次模板和照片，不因无关原始附件缺失而阻断导出；权限和网络错误仍会报错。上述回归未验证真实线上 Worker 或生产存储。

本轮稳定性内测：隔离浏览器完成保研初稿的创建、预览、编辑、保存与 Word 下载，使用的是不调用模型的受限初稿；自然输入中专业、绩点和排名遗漏的问题随后已修复，并以 API 到 Word 回归验证。修复后浏览器在新项目中验证“我叫李明，专业是计算机科学，绩点3.8，排名3/80”均进入草稿；但用“姓名：测试同学”的合成句仍会被第三人过滤规则拦截，同句姓名、专业和成绩未带入，需学生手动补充。另一次隔离浏览器通过本机 `qwen2.5:7b` 单次生成互联网+简介，约 55–82 秒之间返回；等待期间显示状态，完成后输入恢复，未经提供的开发状态和定位方案被提示核对，预览默认不勾选。该结果耗时为观察区间，不代表线上服务性能，生成内容仍需学生审阅。

针对故障注入和代码检查，增加草稿生成中途修订失败时保留旧初稿、避免缺事实时无效重写、逐章生成与学生保存并发时的版本保护、Worker 暂时断网时有限心跳重试、模型请求时间边界和前端观察超时提示；模型调用不会因这些恢复机制自动重发。流式草稿在上游确有增量时会限频报告处理状态，尚无增量时仍可能较长时间不更新。超时后服务端任务及计费状态可能不确定，需要先查看原项目或任务记录。旧版异步任务的进程退出恢复、真实云端 Worker 可用性和线上计费尚未验收；以上措施不能保证服务始终在线或所有生成都能完成。

以下原始问题记录保留用于对照。当前工作区已针对国奖场景增加准备步骤和受限草稿：近期对话中的明确字段及用户确认、姓名匹配的材料可进入草稿；冲突字段留空或提示澄清。实际用浏览器验证了跨轮更正、保存、旧版本查看和 Word 下载，另通过真实 multipart 上传 GBK 合成材料并检查导出 Word 的内容。国奖特定起草路径不调用模型，输出仍是需要补充的草稿，并不等于完整个性化成稿。

第五轮真实本机模型测试中，国家励志奖学金的明确起草请求只返回资料清单，并把学生写的“计算机专业”擅自扩成其他专业全称。现已接入受限草稿及收入偏好处理。隔离浏览器验证了输入姓名、专业、绩点、排名和收入后，再要求不写收入、重新起草、保存和导出 Word；实际文档保留了姓名、专业和成绩，未包含收入或其金额。旧 Word 下载、学校模板、逐章及后台任务的收入偏好也做了隔离测试；本地与模拟云账号的同步及流式起草不调用模型，但真实云端未验收。

真实上传测试覆盖同名材料的辅助身份冲突：多页或多份材料中学号、学校、班级等不一致时不自动合并，仍保留学生对话中自己给出的资料；如果缺少可比较的身份标识，姓名相同仍不足以证明是同一人。个人对话的写作、润色及部分个人数字咨询增加有限的绩点、满分制和志愿时长检查；识别到需要核对的数字时不自动进入草稿，普通解释仍可流式输出。该检查不能涵盖所有虚构事实。

对明确请求起草后的无内部格式标记回复，若具有完整申请书标题、称呼和落款，可作为候选供学生编辑确认；示例、说明和不完整正文不会自动导入。对话发生变化后，已打开的草稿预览需要重新确认，避免按过时要求保存。

第四轮真实本机模型的转专业测试中，学生明确要求起草、提供姓名和原专业及目标专业时，模型只返回清单并自行假设目标专业全称与申请时间。现为明确的转专业起草请求提供受限草稿，并保留多轮已明确提供的姓名、专业与兴趣；资料冲突时留待澄清，缺少的经历、课程认识和学习计划需学生补充。隔离浏览器已复测自然对话、草稿保存与 Word 导出，检查导出文件包含模拟姓名和两个专业、未包含擅自扩写的专业全称。非起草类解释问题仍走模型；本地及模拟云端身份的同步和流式测试验证起草分支不调用模型、不消耗预设试用额度，但未连接真实云端。

学生个人场景的工作台改为显示个人资料及学校通知，隐藏空的大创专用字段；修复切换项目时隐藏事实编辑字段可能保留上一项目数据的问题。个人章节生成新增对部分绩点、满分制和志愿时长表达的检查：没有匹配的学生资料时保留为备选，不自动覆盖正文。该检查只识别有限格式，不能验证所有数字和经历，也不覆盖所有对话和生成类型。

第三轮用隔离本地浏览器实测了优秀学生申请：未发送的输入刷新后恢复，发送后产生草稿，可整理保存并导出 Word；检查生成文件包含测试姓名、专业、绩点和排名。已增加优秀学生、三好学生和优秀团员的受限草稿，缺失经历仍需学生补充。成绩隐去和恢复按明确指令处理；其他赛道的同类指令尚未全部验收。断网或未发送输入暂存于当前标签页的 sessionStorage，按账号和项目隔离，不自动重发；退出账号时清除，浏览器阻止存储时仅在当前页面内存恢复。

真实 multipart 接口内测覆盖单人 Word 表格和可提取文本的 PDF：当前项目中经用户确认、姓名明确匹配的材料可以进入国奖草稿；错人、未确认、多人的表格和跨项目材料不采纳。多页 PDF 仅在每页独立标明相同姓名、字段可明确解析时使用；有无法识别的页面或低置信度 OCR 时不自动采纳。另用两页 PDF 验证了上传、确认、对话、保存和 Word 导出。TXT 和 Word 段落也支持受限提取；未知行、复杂表格及扫描件 OCR 不保证自动识别。

批量上传增加整批格式与大小预检，中文 TXT 支持常用编码。模板缺项或未映射不再显示基础检查通过；真实国奖对话和确认材料可填入简单学校 Word 表格（仅用于本次导出，不改项目事实），冲突时留空。替换已保存的聊天草稿前会保留旧版，界面可查看历史版本。复杂表格、全部 PDF/OCR 和 35 个赛道尚未完成验收。

**仍未通过完整验收**：真实 Ollama 的普通对话仍曾自行推断未提供的绩点满分制，其他赛道的自由生成仍可能编造；云端断线续跑、真实线上账号与计费未在本轮测试。

第二轮助学金内测中，真实 Ollama 用时约 100 秒，虚构了学生没有提供的家庭和个人经历，并遗漏已给出的收入。现已将国家助学金的明确起草请求接入同类受限草稿：重测时保留姓名、专业及家庭年收入，缺少的内容留空，草稿可保存且该路径不调用模型。学生要求不写收入时，草稿省略该内容；旧正文或模板仍包含收入时，导出会要求先处理，并对旧文件下载和后台产物增加检查。对话更新后，页面会撤销旧下载链接并阻止尚在返回的旧文件自动下载。收入偏好目前只回溯最近 200 条消息，已下载至设备的旧文件无法撤回。

逐章生成在检查未完成时保留为备选而不自动覆盖正文；如果备选保存失败，同步结果可在当前页面查看，旧异步任务在任务表可写时保留结果，不自动重复调用。若任务表也无法写入、同步响应中断或页面刷新，仍不能保证草稿留存。检查通过本身不证明事实正确。其他赛道仍需按统一事实来源与生成协议继续验证。

个人章节在没有相关起始资料时不调用模型，保留已有正文或给出待补充占位；明确要求不用个人资料或国家助学金不写收入时，自动生成暂缓并保留正文，避免将已有敏感信息送入该次生成。该检查只覆盖近期 200 条对话、有限的个人章节标题和指定意图，不能替代对其他生成路径的事实与隐私审查。

## 范围

- 当前本地工作区；临时 SQLite、合成学生数据，本机 Ollama `qwen2.5:7b`。没有访问生产数据或调用付费模型。
- 用浏览器实际操作“新对话 → 国奖申请书 → 整理保存 → 导出 Word → 再次起草”，并通过隔离 API 检查材料上传、两类申报及导出文件。
- 国家助学金模板测试使用固定模拟模型答复，只验证文档处理链路；不代表真实模型能正确完成写作。没有逐一验收全部 35 个 Skill、线上登录和计费。

## 可以完成的路径

在国家奖学金的“询问条件并写申请书”特定路径中，学生输入姓名、专业、绩点和排名后，系统识别国奖赛道并返回包含这些信息的占位草稿。浏览器中可选择“从对话整理草稿”、确认保存，并成功生成、下载 Word。隔离测试读取导出的 docx，确认含姓名和排名；文档仍有多处待补充字段，且使用通用排版。

## 阻塞问题

1. **真实模型编造事实，正文也无法保存。** 学生明确说明没有科研经历、要求不要编造并直接写正文，Ollama 仍生成了未经提供的入学年份、政治面貌、课程成绩、志愿时长和学生工作经历；输出没有被识别为可保存草稿，却提示可以整理保存。另一次明确要求写申请书时，模型只返回了信息收集清单，未产生正文。模型输出存在不确定性，上述为实际测试结果。
2. **多轮重写丢失资料。** 首轮“申报条件是什么？帮我写申请书，我叫李明，学计算机专业，绩点3.8，专业排名3/80”正确填入信息；下一轮“申报条件是什么？请重新写一份申请书”却把姓名、学习情况重新变成待补充。草稿整理优先保留同标题最新版本，可能使用户看到的候选不含此前资料。浏览器和隔离 API 均复现。
3. **已上传材料未进入国奖草稿。** 上传并确认的合成 TXT 包含学院和竞赛获奖信息，但国奖占位草稿及 Word 未使用这些信息，依然显示待补充；对话中当轮给出的姓名和排名则进入了 Word。
4. **学校模板表格未填入，检查结果易误导。** 国家助学金测试中，上传学校 DOCX 表格模板后导出返回成功，但模板里的姓名和家庭年收入占位未填，正文附在模板后面；接口同时返回 `validation.passed=true` 和排版评分 100，另有未填充警告。此测试的模型正文为固定模拟内容。
5. **自然问题被误判为纯政策问题。** 输入“我想申请国家奖学金，我的专业排名是3/80，应该怎么准备？”，系统仅表示未查到官方依据并要求补充信息，没有回答准备步骤。
6. **发送失败可能丢失输入。** 前端模拟请求开始即断网且服务端未收到消息：发送前输入框被清空，刷新历史后聊天里也没有该段文字，只剩连接中断提示。测试使用 DOM harness；没有发生付费调用。
7. **批量上传部分成功却报告失败。** 同时上传合法 TXT 与不支持的 `.doc`，接口对后一个文件返回 415，但前一个 TXT 已保存；学生按整体失败提示重试后，同名 TXT 会重复出现。此项在本地 API 路径复现，云端分片上传未验证。
8. **部分中文 TXT 乱码未提示。** 合成 GBK 编码中文 TXT 被标记为识别完成且无警告，提取文字为替换字符。学生可能误以为内容识别正常。

## 界面与材料体验

- 国奖场景仍显示“大创立项模拟评审”“预算”等不相干内容，快捷建议包含家庭经济、勤工助学；学生容易误解赛道重点。
- 国奖导出的文档出现默认项目名“新对话”和通用草稿提示；固定占位文本距离可直接用于申报的完整正文仍有明显差距。
- 对话正文需要满足内部格式才可自动整理为章节；真实模型未稳定遵循该格式，不能以接口返回 200 认定写作和导出链路可用。

## 修复和复测顺序

优先解决真实事实与多轮信息连续性，再打通“模型正文 → 可编辑草稿 → 学校模板”，然后修复断网保留输入和上传结果一致性。最后按国奖、助学金及项目立项分别以真实材料和可控模型做浏览器端回归，再验证线上身份、计费与部署版本。
