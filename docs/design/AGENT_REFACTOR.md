# 学生申报 Agent：现状与重构路线

本文记录当前代码与下一步的边界。目标是提供自然、连续的申报辅导对话，并按所选赛道调用现有 Skill、资料检索和材料生成能力。这里借鉴公开的 Agent 设计原则，不声称复现 ChatGPT 或 Claude 的内部实现。

## 当前链路

```text
工作台先对话，或选择材料赛道
  → 需求明确时识别并绑定 Skill
  → 项目对话 API（权限、基础信息、免费次数 / 计费）
  → ChatRuntime（上下文、模型与工具循环）
  → Ollama 或 OpenAI Chat Completions 兼容模型
  → 受限工具（赛道指南、资料检索、来源核验等）
  → 保存消息并通过 SSE 或普通响应返回
```

- `server/proposal/chat_runtime.py` 是普通回复和流式回复共用的对话循环；`chat_context.py`、`chat_tools.py`、`chat_model.py` 分别处理上下文、工具授权和模型事件。`openai_adapter.py` 统一 OpenAI 兼容协议的请求转换；`agent.py` 仍负责模型传输、计费衔接及其他生成操作。
- `server/proposal/skills.py` 从 `index.json` 获取赛道元数据，提供只读技能目录和当前赛道的按需指南。当前注入的是过滤后的摘录，不等于通用 Agent Skills 运行时，也不支持自动运行任意 Skill 脚本。
- 学生确认后的项目资料和公开资料通过现有工具检索；章节、图表、导出和模拟评审使用工作台的确认入口。事实保存仍由专用工具核验用户确认与原文。
- 本地消息存储使用 SQLite，云端使用 Supabase。新消息包含微秒时间；历史云端消息如果时间戳相同，无法仅凭时间戳还原确切顺序。
- 工作台有旧的章节生成链路，也有使用独立 worker 的材料任务链路；并非所有 Skill 都有专属模板和完全相同的导出能力。

## 本次已完成

1. 两种对话输出共用一套上下文、工具调用和结束逻辑；读取历史时先快照，再追加本轮消息。
2. 对话工具执行时检查实际允许列表，并由服务端指定项目 ID；模型不能通过伪造调用绕过章节保存、导出和评审的确认入口。
3. 工具调用前的临时流式文字会被清除，最终结果不再与中间文字拼接。Ollama 流必须收到结束标记，断流不能被当作完整回复。
4. 修复免费流式请求在模型通道未启动时丢失体验次数的问题，并统一平台流式输出长度上限。
5. 对话指令优先回应当前请求，不强制所有问题从模板询问开始；不再用截断问号的方式删掉问卷或正文内容。
6. 清理模型上下文中的示例段落：实际本地模型曾将国家奖学金 Skill 中的示例姓名、专业和排名写入回答。现在会过滤示例段、引用块和部分示例数字，并要求未知个人信息使用占位符。复测中模型未再复制具体身份数据，但仍曾自行写出“优异的成绩”，因此尚不能保证事实真实，必须核对。
7. 提供无需预选赛道的对话入口，明确识别时绑定 Skill；已选项目不会因后续聊天静默切换。修复政策关键词误拦写作请求，以及兼容模型遗漏工具调用 ID 导致后续请求失败的问题。
8. 对可拆分的混合请求，将政策检索与写作分别处理：政策依据使用原有检索路径，写作通常走用户选择的模型与计费路径；不可安全拆分时仍只返回依据。特别是“查询政策并起草国家奖学金申请书”，在逐条事实溯源完成前暂时返回占位草稿，不调用模型。用户在本轮用明确字段或部分自然表达提供的姓名、学院、专业、绩点和排名可填入草稿；不读取旧资料或附件，歧义内容保持空缺。其他混合写作的输出过滤只是启发式，不是事实校验；流式草稿须等待完整结果再显示。
9. 新增隔离的本地任务账本及 Worker 原型（`chat_turns.py`、`local_chat_worker.py`），用于验证幂等提交、租约和不确定结果。只在本地显式启用时开放实验 API，网页尚未使用它；仅支持本地 Ollama，输入仍在进程内存中，不具备重启后自动恢复能力。
10. 技能指南可在过滤后分页读取，避免多数长指南只暴露开头；工作台对项目加载和聊天响应增加切换竞态保护。
11. 国奖和国家助学金的明确起草使用受限的多轮资料整理和可编辑初稿；已确认且身份匹配的材料可补充部分字段。学校模板只对可识别的字段填充，未映射或仍有空缺时不声称基础检查通过。学生不写家庭收入的选择会约束助学金草稿和导出；偏好目前只回溯最近 200 条消息。
12. 对话草稿可主动选择替换已保存正文，旧正文先保存为历史版本；章节检查未完成时不自动覆盖。备选保存失败的结果在响应和当前页面中暂存，不重试模型；断线、刷新或任务存储同时失败时仍不能保证恢复。

### 本地实验 API

仅本机开发时设置 `LOCAL_CHAT_WORKER_ENABLED=true`。对已选赛道的项目，`POST /api/experimental/local-chat/{project_id}/turns` 接收 `message` 和调用方生成的 `idempotency_key`，返回任务 ID 和状态；通过 `GET /api/experimental/local-chat/{project_id}/turns/{turn_id}` 查询结果。相同键与相同请求不会重复调用，键对应不同输入会返回冲突。正式网页仍使用现有对话接口，云端即使设置此变量也不会启用该实验 API。

此实现是单进程本地原型：完成结果保存在本地账本，但账本与消息不在同一事务；发生进程退出、租约过期等情况时可能需要核对，不支持后台自动重启或云端恢复。

## 尚未解决的结构性问题

1. **对话依赖当前 HTTP 请求。** 浏览器断开、Vercel 函数到达时限或进程退出时，尚无持久化执行状态与断线续传，不能保证后台继续执行。现有消息表只是对话历史，不是可恢复的任务日志。
2. **对话入口仍复用项目数据结构。** 新入口可先对话再匹配赛道，或在尚未确定时手动选择；不支持将已有赛道的项目直接切换为其他赛道。旧的 `/api/projects/start` 入口仍是大创专用。
3. **Skill 挂载仍是静态适配。** 指南会被过滤和截断；按需加载 `references/`、使用各 Skill 专属构建器和检查输出质量尚未全部接通。
4. **模型传输仍集中在 `OllamaAgent`。** 名称和职责已经超出 Ollama，普通和流式 HTTP 适配、付费用量及其它写作操作还在同一个模块；当前支持 Ollama 和 OpenAI Chat Completions 兼容接口，不代表已接入 Claude 原生 API。
5. **并发与重试尚未形成完整协议。** 不能仅靠前端按钮避免跨设备并发；付费请求遇到上游结果不明时必须先核账，不能自动重放。
6. **行为偏好还没有独立的版本化配置。** 当前只有通用对话原则和各赛道 Skill；用户个人的思维方式需要以明确提供的偏好为依据逐步整理，不能假定系统已经知道。

## 建议的后续顺序

1. **持久化对话执行**：为每轮引入独立 run ID、用户及项目归属、幂等键、状态和可重放事件；在独立 worker 中运行并支持重新连接。先明确等待用户、失败和账单待核对等状态，再设计数据库迁移与权限。上游结果不明时禁止自动重放付费推理。
2. **自然入口和渐进式路由**：允许先描述需求；有明确赛道时加载对应 Skill，歧义时展示候选并保存选择。普通分析、正式起草、文档导出分别有明确的操作边界。
3. **Skill 运行协议**：区分元数据、指导正文、按需引用、结构化输入和构建器。逐赛道验证生成物和学校模板适配，不将示例或过期规则当作事实。
4. **独立模型适配层**：按实际接入需要分离 Ollama、OpenAI 兼容协议以及将来可能接入的原生协议，统一工具调用、流式事件、超时与费用契约；模型接入必须经真实账户与费用验收。
5. **评测与可观测性**：建立覆盖真实申报对话的匿名评测集，检查路由、引用、连续追问、生成质量、断线、计费和导出。对外显示任务状态，对内保留不泄露材料与密钥的可关联诊断信息。
