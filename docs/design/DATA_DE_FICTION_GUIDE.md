# 示例数据去虚构化规范（子 Agent 共用）

> 本文件是 6 个并行改造 Agent 的**唯一判据来源**。
> 读到这里就等于知道该改什么、不该改什么、怎么验收。

## 背景

用户反馈「AI 味太浓」。前置工作已完成：

- 已注入统一写作规范块（35/35 子 skill）
- 已把大章节外移到 `references/`（渐进式披露）
- 已改造 6 个 skill 的「金句模板」
- 已建 AI 味检测器 `utils/ai_flavor_check.py`

**本轮剩余工作**：35 个 SKILL.md 里仍有大量**虚构示例数据**
（如「消防无人机项目」「井冈山蜂蜜 36 条视频 120 万次播放」），
模型会把这些当成真实案例照抄进用户申报书，等于**替用户编造事实**。

## 核心原则

> **示例可以保留，但必须让模型明白「这是示例，不是可直接使用的数据」。**

不要删除示例（示例对模型理解结构很有价值），而是：

1. 把具体数字改成**占位符**或**带标注的示例**
2. 在示例块前加**显式警示**
3. 保留结构和逻辑，去掉「可照抄性」

## 改造判定：三类内容，三种处理

### A 类：真实可查的公共事实 → **保留**

政策文号、法规名称、官方数据、真实赛事名称、真实项目名称。

例：
- `《"十四五"国家应急体系规划》（国发〔2021〕109 号）` → 保留
- `1922 年 5 月 5 日，中国社会主义青年团第一次全国代表大会在广州召开` → 保留
- `财教〔2024〕181 号` → 保留

**判断方法**：这条信息能不能在政府网站/权威媒体上查到？能查到就保留。

### B 类：虚构但带标注的示例 → **改为占位符或加警示**

典型：「消防无人机项目」贯穿 challenge-cup 的范文。

处理：
- 保留示例（帮助模型理解结构）
- 在示例块前加一行警示：`> ⚠️ 以下为示例，数字均为虚构占位，必须替换为用户真实数据`
- 把易被照抄的具体数字改为 `[N]` / `[X]%` 形式，或保留但明确标注

### C 类：AI 生成的抒情套话 → **删除**

无出处、无信息量、可被任何申请人替换的句子。

例：
- ~~「团队深入学习井冈山精神，将'敢闯新路'内化为蜂蜜电商模式创新」~~
- ~~「青春的意义不在于获得什么，而在于奉献什么」~~

**判断方法**：这句话换个人写还成立吗？成立就是套话。

## 具体改造动作

### 动作 1：示例块加警示头

在示例/范文块前插入：

```markdown
> ⚠️ **示例数据，不可照抄**：下文数字（次数/人数/金额/百分比）均为虚构占位，
> 必须替换为你项目的真实数据。照抄 = 编造事实，评审核查即为不诚信。
```

### 动作 2：数字改占位符

| 改造前 | 改造后 |
|---|---|
| `累计开展党史学习教育 12 次、学习时长 36 学时` | `累计开展党史学习教育 [N] 次、学习时长 [N] 学时` |
| `发布短视频 36 条，累计播放 120 万次` | `发布短视频 [N] 条，累计播放 [N] 万次` |
| `精准帮扶 156 户蜂蜜养殖户` | `精准帮扶 [N] 户` |
| `30 秒内响应、5 公里半径覆盖` | `[N] 秒内响应、[N] 公里半径覆盖` |

### 动作 3：抒情句删除

直接删掉 C 类句子，或替换为「填空式结构」：

```markdown
<!-- 改造前 -->
团队深入学习井冈山精神，将"敢闯新路"内化为蜂蜜电商模式创新。

<!-- 改造后 -->
[精神名称] 如何指导项目：[具体做法]。例：把"敢闯新路"落到
[你做的具体创新动作]，结果是 [可核查结果]。
```

## 绝对禁止

- ❌ 删除政策文号、法规名称等真实事实（A 类必须保留）
- ❌ 大段删除原文（会丢失结构信息，导致模型写不出该章节）
- ❌ 改动 `## 写作风格硬约束（去 AI 味 · 强制）` 块（受保护，改了会被门禁打回）
- ❌ 改动 `<!-- REFERENCES-INDEX -->` 索引块
- ❌ 改动 frontmatter 的 `name`（必须与目录名一致）
- ❌ 新增 `## ` 标题到受保护块内部

## 每个 skill 的改造流程

```bash
cd "/Users/anna/Desktop/agentskill 大创/awesome-student-ai-skills"

# 1. 找出该 skill 的虚构数据
grep -n "井冈山\|消防无人机\|某村\|XX 学院\|张三" subskills/<id>/SKILL.md

# 2. 逐处改造（用 edit 工具，不要整文件重写）

# 3. 自检：受保护块必须完整
grep -c "WRITING-STYLE:START" subskills/<id>/SKILL.md   # 必须 = 1
grep -c "WRITING-STYLE:END" subskills/<id>/SKILL.md     # 必须 = 1

# 4. 自检：build.py 仍可运行
cd subskills/<id> && python3 build.py --demo --out /tmp/<id>.docx && cd ../..

# 5. 自检：同步 README KB（若文件大小变了）
python3 scripts/sync_readme_kb.py

# 6. 自检：门禁
python3 scripts/check_doc_consistency.py
python3 scripts/inject_writing_style.py --check
```

## 验收标准（Lead 会逐项检查）

| 检查项 | 标准 |
|---|---|
| 写作规范块 | 35 个文件各 1 个 START + 1 个 END，未被破坏 |
| REFERENCES-INDEX | 未被改动 |
| frontmatter name | 与目录名一致 |
| build.py | `--demo` 能生成 docx |
| 文档一致性门禁 | 通过 |
| 示例数据 | 关键虚构数字已改占位符或加警示 |
| 抒情套话 | 已删除或改为填空结构 |
| 真实事实 | 政策文号等未被误删 |
