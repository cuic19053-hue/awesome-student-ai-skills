# 写作风格规范（去 AI 味）— 单一事实来源

> 本文件是**唯一权威版本**。35 个子 skill 的 SKILL.md 只保留压缩后的引用块，
> 详细展开与判据都在这里。修改规范请改本文件 + 重跑 `scripts/inject_writing_style.py`。

## 0. 为什么有这份规范

用户反馈（2026-11-08）：「skill ai 味太浓了」。

根因不是模型能力，而是**指令自相矛盾**：子 skill 里一边写「禁用套话」，
一边提供「金句模板（可直接套用）」「必用句 10 句」「完整范文」。
模型优先照抄模板，于是稳定输出排比腔与空话腔。

规范的作用：提供文风复核线索和改写建议。事实须由用户确认，启发式分数不能决定交付。

---

## 1. 一条总原则

> **每个句子都必须能落到具体的人、事、时间、数字或对象上。
> 落不到的句子，删掉。**

判断方法：读完一句问「这句能换成别人吗？」——能换，就是套话。

---

## 2. 六个维度与参考分

用 `utils/ai_flavor_check.py` 辅助检测，满分 100，75 分仅供参考；人工结合上下文核对，不以分数作为交付或评审的硬门槛。

| 维度 | 判据 | 典型失分写法 |
|---|---|---|
| 空话套话 | 每千字命中套话 ≤3 次 | 「具有重要意义」「高度重视」「不懈努力」 |
| 排比对仗 | 同构句连续 ≤2 句 | 「在思想上…在学习上…在工作上…在生活上…」 |
| 抽象名词 | 每千字抽象大词 ≤4 次 | 「体系」「机制」「闭环」「赋能」「格局」 |
| 具体性 | 每千字数字/专名 ≥8 处 | 通篇无数字、无课程名、无项目名 |
| 句长分布 | 句长变异系数 ≥0.35 | 每句都是 25~30 字 |
| 模板首尾 | 不用时间感慨式开头 | 「时光荏苒」「本人自入学以来」 |

```bash
python3 utils/ai_flavor_check.py --file draft.txt
```

## 4. 替换动作（仅使用已核实事实）

缺少事实时向用户询问、保留占位或省略，不得为提高得分编造。

| 原写法 | 改写成 |
|---|---|
| 学习成绩优异，名列前茅 | 写具体：专业 `<排名>/<总人数>`，加权 `<成绩>`，`<课程名>` `<分数>` |
| 积极参加学科竞赛 | 写具体：`<获奖时间>` `<赛事全名>` `<奖项>`，作品 `<名称>`，我负责 `<模块>` |
| 在导师指导下参与科研 | 写具体：参与 `<导师>` 的 `<课题名>`，负责 `<具体工作>`，产出 `<论文/专利/数据>` |
| 具有较强的团队协作能力 | 删掉。改为一件协作事实：`<时间>` 带 `<人数>` 人完成 `<任务>`，遇到 `<冲突>`，怎么解决的 |
| 思想上积极向党组织靠拢 | 写具体：`<年/月>` 提交入党申请书，`<年/月>` 成为积极分子，参加 `<次数>` 次党课 |
| 热心公益，积极参加志愿服务 | 写具体：`<机构>` 志愿服务 `<小时>` 小时，服务 `<对象>` `<人数>` 人 |

## 5. 句式要求

1. **长短句交替**：每 3~5 句里至少有一句 ≤12 字或 ≥60 字。
2. **一段一个事实**：每段只讲一件事，段首句不要用「在……方面」。
3. **少用第一人称抒情**：「我深深感到」「我深刻认识到」一律删除。
4. **事实优先**：仅用用户确认的数字；次数或数量未知时追问或保留原意。
5. **不用破折号堆叠解释**，不用「不仅……而且……」连续套用。

## 6. 与「引用政策原文」的冲突处理

政策条文、领导讲话、文件原名**允许庄重书面语**，不视为套话。
检测时加 `--allow-policy-quotes`，该维度扣分减半。
但引用必须：`《文件全名》（发文号）` 格式 + 只引与论点直接相关的 1~2 句。

## 7. 质检流程

交付前核对内容和事实；文风检测仅作辅助，人工判断建议是否适用：

```bash
python3 utils/ai_flavor_check.py --file draft.txt
python3 utils/plagiarism_checker.py --list-skills
# 例：仅当赛道对应 grant_application 时
python3 utils/plagiarism_checker.py --file draft.txt --skill grant_application
python3 utils/review_simulator.py --list-skills
# 例：当赛道对应 grant_application 时
python3 utils/review_simulator.py --skill grant_application --text-file draft.txt
```

查重及评审模拟仅支持列出的赛道；不支持时不能声称完成赛道模板查重。不能因为工具不支持或启发式分数低就拒绝交付。

## 8. 反模式

- ❌ 把「金句模板」当范文直接套用
- ❌ 用排比段凑字数
- ❌ 通篇无一个数字、无一个专有名词
- ❌ 仅凭检测分数决定交付，或为提高分数编造事实
- ❌ 只删套话不补事实（删完变成空段落，同样不及格）

## 9. 检测器边界（哪些内容不参与评分）

`ai_flavor_check.py` 只评估**散文正文**。以下内容即使结构雷同也不算 AI 味，
检测器会自动排除：

| 内容类型 | 排除原因 |
|---|---|
| Markdown 表格行 `\| a \| b \|` | 表格结构相同是格式要求 |
| 列表项 `- xxx` / `1. xxx` | 列表结构相同是格式要求 |
| 引用块 `> xxx` | 引用格式 |
| ASCII 框图（`┌─┐│└┘` 等） | 图表，非文字表达 |
| 围栏代码块内的代码 | 代码，非文字表达 |
| 档位参数说明 `**短版（约 360 字）**：…` | 规范说明，非正文 |
| 分号列举 `A；B；C` | 中文并列的正常书面语（不按分号切句） |
| 纯框图 / 纯表格文本 | 无可评散文，返回「无散文内容」而非低分 |

**重要**：包在 ``` 围栏内但实际是范文正文的内容**仍会参与评分**
（检测器会识别中文占比并保留），避免「把范文包进代码块就绕过检测」。

---

## 10. 评分口径（真阳性 vs 真阴性）

检测结果是启发式提示，不是事实真实性或文本质量的确定性判定。应根据上下文审查命中项，对误报予以忽略；不得为满足数字密度而虚构事实。
