# 对话与计费异常专项检查（2026-10-28）

范围：平台模型/自带 Key 的请求重试、流式回复完整性、结算异常、后台对账、
用户界面状态和计费回归门禁。不是对整个产品的“无缺陷保证”。

## 已复现并修复

| 问题 | 风险 | 修复 |
| --- | --- | --- |
| 每个 SSE 小段都查询云端钱包 | 长回答产生大量串行 RPC，变慢并容易超过服务端时限 | 钱包信息每轮只读取一次；25 个文字片段从 27 次读取降为 1 次 |
| 模型成功后结算 RPC 抛异常 | 已生成回答也显示失败，用户可能再次付费调用 | 已确认的模型回答继续返回，账本异常留给后台核对；不再次调用模型 |
| 超时、断流自动重发模型请求 | 上游可能已经执行，重复调用、重复片段和费用无法确认 | 平台调用不自动重发；兼容 API 仅保留无输出前的 429 重试 |
| 流式 HTTP 正常结束但没有完成标志 | 截断回复被当作完整回答 | 后端要求终止标志，前端要求应用 `done` 事件；断流明确提示未完成 |
| 完成但空白的流式回复 | 空白答复被当作成功结算 | 与非流式回复一致，拒绝空白并执行已有空答复处理策略 |
| 5xx 被当作确定未执行 | 错误释放实际可能已发生的预留 | 文本、Worker 代理和图片都区分明确拒绝与不确定网关错误 |
| 服务账户登录锁无限等待 | 两秒查询超时并不限制等待登录锁的时间 | 登录锁使用有期限的等待，网络登录只使用剩余时间 |
| 结算 RPC 默认等待 20 秒 | 服务端快到执行期限时仍等待账本，丢失最终响应 | 后台启用时同步结算使用短超时，失败交后台 |
| 非法 token 统计字段 | 正文已经生成，仍因统计字段格式而报错 | 非计费统计按类型验证，不丢弃正文；实际账单继续独立核验 |
| 所有 SQLSTATE 55000 都提示“正在核对” | 无关数据库异常被误报为账单挂起 | 只有旧锁的明确错误标记才映射为该提示 |
| 本地退款流水的模型/引用字段颠倒 | 审计与追踪错误 | 修复字段顺序并校验流水 |
| CI 没有运行新增计费 PostgreSQL 集成测试 | 本地通过的回归约束未进入持续门禁 | 将隔离计费集成测试加入 CI |

故障注入最初复现：Python 新增的前 10 个用例中有 8 个失败；
真实 SSE 分支新增的 2 个前端用例均失败。修复后再运行，不以“先改测试预期”
掩盖失败。所有测试使用隔离数据或模拟上游，不使用真实用户凭据。
原有“503 自动重试”测试与本次避免重复计费的策略冲突，已明确改为“429 可重试”，
并新增“自带 Key 的 503 也不得自动重发”测试，而非保留不安全的旧行为。

上线另需验证：独立测试账号真实 SSE 回复、带历史挂起记录仍可继续调用、
余额查询不访问上游、后台 Cron 实际 HTTP 响应、告警与去重。
不能把独立测试账号的成功当作原受影响用户已恢复的证据。

## 仍需保留的边界

- 云端每个模型候选设置 45 秒执行预算，后续工具轮次预算耗尽时不再预留。
  网络超时不是严格的总墙钟限时；慢工具、数据库或平台中断仍可能使请求失败。
- 上游长期缺失收据时仍需人工核对/按平台政策兜底，预留可能影响可用余额。
  不根据超时猜测零费用。
- 兼容流式接口需发送 `[DONE]` 或 `finish_reason`；非标准接口会得到明确错误，
  而不是被当作成功。
- 前端单标签页禁止重复发送，账本请求 ID 幂等不等于跨标签页的业务请求幂等；
  持久的整轮对话去重仍未实现。
- 定时对账和告警有容量、调度及通知依赖，不能承诺永不发生故障。
