# 排版硬指标（Layout Standard）

> 这份文件定义「什么样的 Word 文档算过关」。
>
> 它不是审美建议，而是**可机器验证的条款**：每一条都有编号、判据、检测方式和实现手法。
> 执行自检：`python utils/layout_audit.py <docx 或目录> --render`
>
> 适用范围：所有 35 个子 skill 生成的 `.docx`，以及任何通过本仓库 skill 产出的申报书、申请书、个人陈述。

---

## 0. 为什么需要这份规范

评审老师看一份申报书的前 30 秒，判断的不是内容深浅，而是**这份材料是否被认真对待过**。字体字号只决定第一眼，真正暴露「模板直接套」的是这些细节：

- 一张 8 行的表格被撕成 6 行 + 2 行，第二页只剩孤零零两行没有表头；
- 图在第 6 页底部，图注「图 3　技术路线」跑到第 7 页顶部；
- 正文写「如下图所示」「详见下表」，全文 50 张表却没有一处带编号指代；
- 章标题从「一、」跳到「三、」，或者小节号写成 `2.1 / 2.2 / 2.4`；
- 页脚空白，打印出来散页后无法排序；
- 封面把机构名印了两遍（红头一行、黑体一行，字一模一样）。

这些不是排版风格问题，是**可直接判定的缺陷**。下面 13 条静态条款 + 5 条渲染条款，就是把这批缺陷逐条堵住。

---

## 1. 标准分级

| 级别 | 含义 | 未达标时 |
|---|---|---|
| **A 级（红线）** | 直接影响评审对材料专业度的判断，或导致信息错乱 | 不得交付，必须修复 |
| **B 级（应做）** | 影响可读性与可维护性，多数正式材料都做到了 | 不修要能说清原因 |
| **C 级（加分）** | 无障碍、可编辑性、长期可维护 | 视交付场景决定 |

`layout_audit.py` 中 A 级 = `FAIL`，B/C 级 = `WARN`；默认达标线 **90 分**（每处 FAIL 扣 12 分、WARN 扣 3 分）。

## 2. 静态条款（只用 docx XML 判定，CI 可跑）

### L01 章号连续 —— A 级

**判据**：形如 `一、二、三…` 的章标题，序号必须严格递增、无跳号、无重号。
**为什么**：跳号意味着中间删过一整章却没重排，评审会顺手翻回去找「缺的那章」。
**检测**：`L01`。提取所有匹配 `^[一二三四五六七八九十]+、` 的段落，转整数后比对 `n+1`。
**常见错法**：手工维护章号，插章后忘了改后面的。
**实现**：章节标题由 `h1()` 输出，序号用 `cn_num(计数器)` 生成，永远不手写。

### L02 小节号与所属章一致 —— A 级

**判据**：`N.M` 形式的小节号，`N` 必须等于当前章序号，`M` 从 1 连续递增。
**为什么**：`三、` 章下面出现 `4.1` 是典型的「复制上一份文档」痕迹。
**检测**：`L02`。
**实现**：写完正文后统一跑一遍重排，按「所在章.序」重算（参考 `scripts/docx_kit.py: renumber_subheads()`）：

```python
for p in doc.paragraphs:
    if 匹配 H1:            cur_ch = cn_int(章号); seq = 0
    elif 匹配 ^\d+\.\d+:   seq += 1; 把 "旧号" 替换成 f"{cur_ch}.{seq}"
```

### L03 图表编号连续 —— A 级

**判据**：图注 `图 1　…`、表题 `表 1　…` 各自从 1 开始连续，无重号、无跳号。
**检测**：`L03`。
**实现**：编号由文档级计数器分配（`doc._tab_counter`），不要在两处分别写死。

### L04 图表引用闭环 —— A 级（最常被忽略的一条）

**判据**：**每一个**编号图/表，都要在正文里至少被提到一次编号；正文提到的编号不得超出实际数量。
**为什么**：只有编号没有引用，编号等于装饰。读者在 15 页里没法凭「如下图所示」定位到第几张图。
**检测**：`L04`。
**常见错法**：正文写「如下图」「见下表」；或表紧跟在标题后，前面根本没有正文段可以挂引用。
**实现**：两层兜底。

1. 输出图表的当下，回改紧邻的上一段正文：以冒号结尾的引导句改成「如图 3 所示：」，否则句末补「（见图 3）」。原文已经点过号的就跳过，不重复补。
2. 构建收尾跑一遍全文兜底 `cite_all(doc)`：从图表位置向前找最近一段正文（跳过空段、题注、图片、表格），撞上标题就改为从图表之后找本篇第一段正文（遇下一个标题即停）。同段已有「（见表 4）」时并入成「（见表 4、表 5）」，不叠第二个括号。

```python
# 判据里的边界：中文字词内的「表」「图」不算引用
CITE_TAB = re.compile(r"(?<![发代图报仪外])表\s*(\d+)(?!\d)")
CITE_FIG = re.compile(r"(?<![意试企地])图\s*(\d+)(?!\d)")
```

> 反面教训：「累计**发表 14** 篇短文」会被朴素正则 `表\s*(\d+)` 误判成「引用了表 14」。审计器必须带这个负向断言。

### L05 参考文献编号与引用 —— A 级

**判据**：文末文献列表 `[n]` 从 1 连续；有文献列表时，每条至少被正文引用一次。
**检测**：`L05`。
**红线**：**不得编造文献**。作者、刊名、年卷期齐全是编造的特征——看着越完整的假文献越危险。只写能在知网 / Web of Science / arXiv 查到的东西；查不到就写「项目组内部测试数据」。

### L06 页码 —— A 级

**判据**：页脚有 `PAGE` 域（并建议带 `NUMPAGES`），且封面不显示页码。
**为什么**：申报材料经常被拆页复印、评审分组传阅，无页码的材料散页后无法排序。
**检测**：`L06`（读 `sectPr` 的 footer XML 里是否有 `instrText` 含 PAGE）。
**实现**：字段要写全三段，只写一个 `instrText` 在很多渲染器里不刷新：

```python
def field_run(p, instr, placeholder="1"):
    r = p.add_run(); fc = OxmlElement("w:fldChar"); fc.set(qn("w:fldCharType"), "begin"); r._r.append(fc)
    r = p.add_run(); it = OxmlElement("w:instrText"); it.set(qn("xml:space"), "preserve")
    it.text = f" {instr} "; r._r.append(it)
    r = p.add_run(); sep = OxmlElement("w:fldChar"); sep.set(qn("w:fldCharType"), "separate"); r._r.append(sep)
    p.add_run(placeholder)                      # 打开文件前的占位值
    r = p.add_run(); end = OxmlElement("w:fldChar"); end.set(qn("w:fldCharType"), "end"); r._r.append(end)

sec.different_first_page_header_footer = True   # 封面不显示页码
```

### L07 表格不可拆行 —— A 级

**判据**：每个表格的每一行都带 `w:cantSplit`。
**为什么**：不设时，一行内容（尤其是一行里有三行文字的说明）会被从中间劈开，上半截留在页底、下半截跑到下一页顶部。
**检测**：`L07`。
**实现**：

```python
for row in table.rows:
    row._tr.get_or_add_trPr().append(OxmlElement("w:cantSplit"))
```

**整表不跨页（行数 ≤ 13 时追加）**：除最后一行外，所有单元格段落设 `keep_with_next` + `keep_together`，让整表一起换页。

> 代价要认：整表换页会在上一页底部留白。实测 61 张表里只有 7 张会跨页，且全部断在最后 1–2 行（widow row），改成整表不跨页后页数零增加。但**不要**对 15 行以上的大表用这招，否则会留出半页空白（见 R04）。

### L08 长表表头重复 —— B 级

**判据**：行数 ≥ 8 的表，首行带 `w:tblHeader`。
**实现**：`table.rows[0]._tr.get_or_add_trPr().append(OxmlElement("w:tblHeader"))`。
**说明**：与 L07 是互补的——L07 让整表尽量不跨页；确实要跨页的长表，靠 L08 保证每页都有表头。

### L09 表题 —— B 级

**判据**：正文表格上方紧邻一段「表 N　说明」，且该段 `keep_with_next` 与表绑定。
**豁免**（自动识别，不扣分）：封面信息表、单列表格（签字栏/意见栏）、键值信息表（首列形如「项目负责人：」）。
**为什么在表上方**：国标与学术惯例，表题在上、图注在下；表题在下时读者先看到数据不知道是什么。
**常见错法**：表题用普通段落且不绑定，结果表题留在页底、表格跑到下一页。

### L10 图注与图同页 —— A 级

**判据**：图片所在段落 `keep_with_next=True`，紧随其后是「图 N　说明」图注段。
**为什么**：图在页底、图注在下一页是最容易被看见的低级错误，且读者会以为图丢了。
**实现**：图段 `keep_with_next`；图注段 `keep_together`。图不要用行内大图撑满整页。
**注意**：`keep_with_next` 是**段落**属性，对表格行之间的约束在不同渲染器里实现不一。腾讯文档之类的网页预览不认，所以签字栏这类结构必须靠「一栏 = 一行 + 行级 cantSplit」而不是靠段落属性粘合。

### L11 文档属性 —— A 级

**判据**：`core_properties.author` 不含 `python-docx`、不为空。
**为什么**：Word「文件 → 属性」里写着 python-docx，等于告诉对方这是脚本批量生成的。这不是要隐瞒，而是**模板残留**，跟正文里写着「此处填写」一个性质。
**实现**：`cp.author = "…"`，同时设 `title`、`subject`、`last_modified_by`、`keywords`。

### L12 无占位残留 —— A 级

**判据**：全文无 `TODO` / `XXX` / `待填` / `待补充` / `{{ }}` / `[待…]`。
**检测**：`L12`。
**说明**：示例文档里的 `××大学` 属于**刻意的脱敏占位**，不算残留；但交付时必须提醒用户替换。

### L13 标题结构可识别 —— C 级

**判据**：章/节标题段落带 Heading 样式**或** `w:outlineLvl` 大纲级别。
**为什么**：没有结构信息时，Word 导航窗格是空的、目录无法自动生成、屏幕阅读器读不出层级。
**两种做法**：

| 做法 | 视觉影响 | 适用 |
|---|---|---|
| 套 `Heading 1/2` 样式 | 大（字号、颜色、行距、段前后全变） | 从头就用样式的文档 |
| 只写 `w:outlineLvl`（0=章，1=节） | **零** | 版式已手工调好的文档 |

后者是本仓库 11 份示例采用的做法：视觉一字不改，但导航窗格、自动目录、无障碍全部可用。

```python
pPr = p._p.get_or_add_pPr()
el = OxmlElement("w:outlineLvl"); el.set(qn("w:val"), "0")
pPr.insert_element_before(el, "w:rPr", "w:sectPr")
```

> 易踩的坑：`insert_element_before()` 收的是**标签名字符串**（`"w:rPr"`），不是 `qn("w:rPr")`。传后者会 `KeyError: '{http'`。

## 3. 渲染条款（转 PDF 后判定，需 LibreOffice）

静态 XML 看不出「这一页到底长什么样」。以下五条必须真排版后量。

### R01 无跨页表 —— A 级

**判据**：任一页的表格底边触到版心底，且下一页表格顶边触到版心顶，即判定为被拆。
**检测**：`R01`（PyMuPDF `page.find_tables()`）。

### R02 图注未与图分离 —— A 级

**判据**：图注块上方 70pt 内既无位图、也无足够宽的矢量绘制。
**为什么要查矢量**：代码渲染的技术路线图、甘特图是 `get_drawings()` 出来的，没有位图，只查 `get_image_info()` 会全部误报。

### R03 页底孤立标题 —— B 级

**判据**：某页最后一行是短行（< 22 字）、不以句末标点结尾、且不是末页。
**实现**：标题段 `keep_with_next=True` + `keep_together=True`。

### R04 页面填充度 —— B 级

**判据**：底部留白 > 9cm（约版心 1/3）的中间页，占比 ≤ 40%。封面与末页不计入（分别由封面条款与 R05 管）。
**说明**：这条最容易和 R01 打架。整表/整图不跨页，就会在上一页留出空白；把表拆开或把图压小又会违反 R01 与可读性。**永远优先保证 R01/R02**，R04 只用来抓「半页全空」这种明显的失衡。
**实测**：11 份示例文档中，内页留白最大 9.0cm（一张技术路线图整块下移所致），其余多在 7–8cm。真出现 12cm 以上，正确做法是拆小表、缩短表行高、或把一组图改成两栏排版，而不是允许表格跨页。

### R05 末页留白 —— B 级

**判据**：末页底部留白 ≤ 8cm。
**为什么**：末页只有两三行正文、下面空了三分之二，是最直观的「内容不够」信号。常见于审核意见栏过矮（2 个 1.8cm 的栏只占 7cm，剩下 17cm 全空）。
**实现**：意见栏高度**按栏数反算**，让整块大约占满版心 85–90%：`box_h = (23 - 2.4n) / n`（n 为栏数，cm）。裁到 3–8cm 之间。

> 但不要一味加高：块变高后若当前页放不下，会整块跳到下一页，反而在**前一页**留出 13–22cm 空白。逐份实测反推才是稳妥做法（见 `scripts/build_demos.py: SIGN_H`，11 份文档各一个值）。

## 4. 一次性判据（结构性，无法自动检测）

这几条 audit 查不出来，但比格式条款更能决定材料能不能过。

| 判据 | 做法 |
|---|---|
| **每个数字都有出处** | 排名、绩点、获奖、篇幅都要能拿出来源；不写「获得多项荣誉」这类空话 |
| **政策引用带文号** | 「财教〔2019〕25 号」而不是「根据国家政策」 |
| **文献可查** | 见 L05 红线 |
| **章节有正文** | 不允许「五、经费预算」标题下面直接上表，一句说明都没有 |
| **不替用户编事实** | 拿不到的奖项、绩点、导师意见，一律追问，不猜 |

## 5. 自检

```bash
# 静态条款（CI 每次 push 都跑）
python utils/layout_audit.py examples/demos

# 静态 + 渲染条款（本地交付前跑）
python utils/layout_audit.py examples/demos --render

# 机器可读，给 agent 读回来自己改
python utils/layout_audit.py out.docx --json

# 严格模式：WARN 也算不通过
python utils/layout_audit.py out.docx --strict
```

输出示例：

```
── demo_innovation_research.docx ─────────────────
   14 页 · 8 图 · 6 编号表 · 8 文献
   ✅ L01 章号连续
   ✅ L04 图表引用闭环（8 图 / 6 表，全部有引用）
   ❌ [L07] 2 张表未设行级不可拆分，会被从中间撕到两页：['第 4 张（7 行）', '第 5 张（4 行）']
        修法：每行 trPr 加 w:cantSplit；整表 ≤13 行时再给除末行外的段落加 keep_with_next
   得分 76 / 100 · FAIL 2 · WARN 0
```

**退出码**：`0` 达标 / `1` 未达标 / `2` 没找到文件。可直接串进构建脚本：

```bash
python build.py --data data.json --out out.docx && python utils/layout_audit.py out.docx --render || exit 1
```

## 6. 在任何宿主里都能用

这套标准**不依赖本仓库的代码**，条款本身就能驱动任何 agent。

### 6.1 WorkBuddy / Claude Code / Cursor（支持 Agent Skills）

skill 已被加载时，agent 会自动读 `SKILL.md` 与 `references/`。只要在子 skill 的 SKILL.md 里写一条硬要求即可：

```markdown
## 交付前必过（不可跳过）

1. 生成 .docx 后立即执行：
   `python utils/layout_audit.py <输出路径>`
2. 退出码非 0 时，按输出的「修法」逐条改，改完重跑，直到 0。
3. 不要向用户交付未通过审计的文档；若确实无法修复（例如缺 soffice），
   在交付说明里列出未通过的条款编号。
```

**子 skill 的 build.py 只要加三行**，就能把 L06/L07/L08/L10/L11/L13 六条全部补齐（这些条款只依赖 docx 结构，不需要改内容）：

```python
from utils.docx_layout_fix import fix as harden
# …原本的生成逻辑，最后 doc.save(path) 之后：
harden(path)          # 表格防拆 / 图注绑定 / 页码 / 大纲 / 文档属性
```

> 实测：一份「裸奔」文档（普通 9 行表、无页码、属性未清）审计 55 分，
> 跑一次 `harden()` 后 97 分，剩下的 3 分是需要人判断的 L04 图表引用与 L08/L09。

在线工作台（`server/app.py` 的 `/api/projects/{id}/export`）已经内置这一步，
并且在响应里返回 `layout.score`，前端可直接显示「排版质检 xx 分」。

### 6.2 直接粘贴给任意 LLM（无 skill 机制）

把 `references/layout_standard.md` 第 2、3 节的条款表复制进系统提示，再加一句：

> 你生成的 .docx 会经过上述 18 条自动检查。若不满足 L04（图表引用闭环）、
> L07（表格不可拆行）、L06（页码字段），会被判为不合格并重新生成。

### 6.3 无法运行 Python 的宿主

至少做这三件事，能消掉最刺眼的缺陷：

1. 表格：Word 里「表格属性 → 行 → 取消勾选『允许跨页断行』」；
2. 表格首行：「重复标题行」；
3. 图与图注：选中图片段落 →「段落 → 换行和分页 → 与下段同页」。
